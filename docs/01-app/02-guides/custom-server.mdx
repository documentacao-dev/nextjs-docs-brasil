O Next.js inclui o próprio servidor com `next start` por padrão. Se você tem um backend existente, ainda pode usá-lo com o Next.js (isso não é um servidor personalizado). Um servidor personalizado do Next.js permite iniciar um servidor programaticamente para padrões específicos. Na maioria das vezes, você não vai precisar dessa abordagem. No entanto, ela está disponível caso você precise sair da configuração padrão.

> **Bom saber**:
>
> - Antes de decidir usar um servidor personalizado, lembre-se de que ele só deve ser usado quando o roteador integrado do Next.js não atender aos requisitos do seu app.
> - Ao usar o modo de saída standalone, ele não rastreia os arquivos do servidor personalizado. Esse modo gera um arquivo `server.js` mínimo separado. Os dois não podem ser usados juntos.

Dê uma olhada no [exemplo a seguir](https://github.com/vercel/next.js/tree/canary/examples/custom-server) de um servidor personalizado:

```ts filename="server.ts" switcher
import { createServer } from 'http'
import next from 'next'

const port = parseInt(process.env.PORT || '3000', 10)
const dev = process.env.NODE_ENV !== 'production'
const app = next({ dev })
const handle = app.getRequestHandler()

app.prepare().then(() => {
  createServer((req, res) => {
    handle(req, res)
  }).listen(port)

  console.log(
    `> Server listening at http://localhost:${port} as ${
      dev ? 'development' : process.env.NODE_ENV
    }`
  )
})
```

```js filename="server.js" switcher
import { createServer } from 'http'
import next from 'next'

const port = parseInt(process.env.PORT || '3000', 10)
const dev = process.env.NODE_ENV !== 'production'
const app = next({ dev })
const handle = app.getRequestHandler()

app.prepare().then(() => {
  createServer((req, res) => {
    handle(req, res)
  }).listen(port)

  console.log(
    `> Server listening at http://localhost:${port} as ${
      dev ? 'development' : process.env.NODE_ENV
    }`
  )
})
```

> **Defina seus próprios headers de resposta antes de chamar `handle`**: o Next.js começa a enviar a resposta dentro de `handle(req, res)`, então, quando a promise dele resolve, `res.headersSent` já é `true` e qualquer chamada posterior a `res.setHeader()` é descartada silenciosamente. Defina os headers que são seus, como `Set-Cookie`, antes de entregar a requisição ao Next.js:
>
> ```js
> res.setHeader('Set-Cookie', 'sessionId=abc123; Max-Age=2592000')
>
> await handle(req, res)
> ```
>
> A mesma ordem se aplica ao envolver o Next.js em outro framework, por exemplo `reply.raw` no Fastify ou `res` no Express.

> `server.js` não passa pelo Next.js Compiler nem pelo processo de bundling. Garanta que a sintaxe e o código-fonte que esse arquivo requer sejam compatíveis com a versão do Node.js que você está usando. [Veja um exemplo](https://github.com/vercel/next.js/tree/canary/examples/custom-server).

Para rodar o servidor personalizado, você precisará atualizar os `scripts` no `package.json` assim:

```json filename="package.json"
{
  "scripts": {
    "dev": "node server.js",
    "build": "next build",
    "start": "NODE_ENV=production node server.js"
  }
}
```

Alternativamente, você pode configurar o `nodemon` ([exemplo](https://github.com/vercel/next.js/tree/canary/examples/custom-server)). O servidor personalizado usa o seguinte import para conectar o servidor ao app Next.js:

```js
import next from 'next'

const app = next({})
```

O `next` importado acima é uma função que recebe um objeto com as seguintes opções:

| Opção        | Tipo               | Descrição                                                                                 |
| ------------ | ------------------ | ----------------------------------------------------------------------------------------- |
| `conf`       | `Object`           | O mesmo objeto que você usaria no `next.config.js`. Padrão `{}`                           |
| `dev`        | `Boolean`          | (_Opcional_) Se o Next.js deve ser iniciado em modo de desenvolvimento. Padrão `false`    |
| `dir`        | `String`           | (_Opcional_) Localização do projeto Next.js. Padrão `'.'`                                 |
| `quiet`      | `Boolean`          | (_Opcional_) Oculta mensagens de erro que contêm informações do servidor. Padrão `false`  |
| `hostname`   | `String`           | (_Opcional_) O hostname atrás do qual o servidor está rodando                             |
| `port`       | `Number`           | (_Opcional_) A porta atrás da qual o servidor está rodando                                |
| `httpServer` | `node:http#Server` | (_Opcional_) O servidor HTTP atrás do qual o Next.js está rodando                         |
| `turbopack`  | `Boolean`          | (_Opcional_) Ativa o Turbopack (ativado por padrão)                                       |
| `webpack`    | `Boolean`          | (_Opcional_) Ativa o webpack                                                              |

O `app` retornado pode então ser usado para deixar o Next.js tratar as requisições conforme necessário.

## Desativando o roteamento baseado em arquivos \{#disabling-file-system-routing}

Por padrão, o `Next` serve cada arquivo da pasta `pages` em um pathname que corresponde ao nome do arquivo. Se seu projeto usa um servidor personalizado, esse comportamento pode fazer com que o mesmo conteúdo seja servido em vários caminhos, o que pode causar problemas de SEO e de UX.

Para desativar esse comportamento e impedir o roteamento baseado nos arquivos de `pages`, abra o `next.config.js` e desative a configuração `useFileSystemPublicRoutes`:

```js filename="next.config.js"
module.exports = {
  useFileSystemPublicRoutes: false,
}
```

> Observe que o `useFileSystemPublicRoutes` desativa as rotas por nome de arquivo no SSR; a navegação do lado do cliente ainda pode acessar esses caminhos. Ao usar essa opção, proteja-se contra navegações programáticas para rotas que você não quer.

> Você também pode configurar o roteador do lado do cliente para não permitir redirecionamentos do lado do cliente para rotas por nome de arquivo; para isso, consulte [`router.beforePopState`](/docs/pages/api-reference/functions/use-router#routerbeforepopstate).
