O Next.js tem suporte nativo para medir e reportar métricas de desempenho. Você pode usar o hook [`useReportWebVitals`](/docs/app/api-reference/functions/use-report-web-vitals) para gerenciar o envio dessas métricas por conta própria ou, como alternativa, a Vercel oferece um [serviço gerenciado](https://vercel.com/analytics?utm_source=next-site&utm_medium=docs&utm_campaign=next-website) que coleta e visualiza as métricas automaticamente.

## Instrumentação do cliente \{#client-instrumentation}

Para necessidades mais avançadas de analytics e monitoramento, o Next.js oferece um arquivo `instrumentation-client.js|ts` que roda antes do código do front-end do seu app começar a ser executado. Isso é ideal para configurar ferramentas globais de analytics, rastreamento de erros ou monitoramento de desempenho.

Para usar, crie um arquivo `instrumentation-client.js` ou `instrumentation-client.ts` na raiz do seu app:

```js filename="instrumentation-client.js"
// Initialize analytics before the app starts
console.log('Analytics initialized')

// Set up global error tracking
window.addEventListener('error', (event) => {
  // Send to your error tracking service
  reportError(event.error)
})
```

## Crie sua própria solução \{#build-your-own}

<PagesOnly>

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

function MyApp({ Component, pageProps }) {
  useReportWebVitals((metric) => {
    console.log(metric)
  })

  return <Component {...pageProps} />
}
```

Veja a [Referência da API](/docs/pages/api-reference/functions/use-report-web-vitals) para mais informações.

</PagesOnly>

<AppOnly>

```jsx filename="app/_components/web-vitals.js"
'use client'

import { useReportWebVitals } from 'next/web-vitals'

export function WebVitals() {
  useReportWebVitals((metric) => {
    console.log(metric)
  })
}
```

```jsx filename="app/layout.js"
import { WebVitals } from './_components/web-vitals'

export default function Layout({ children }) {
  return (
    <html>
      <body>
        <WebVitals />
        {children}
      </body>
    </html>
  )
}
```

> Como o hook `useReportWebVitals` precisa ser usado em um Client Component, crie um arquivo separado para o componente `WebVitals`, com `'use client'` no topo, antes de qualquer import. Importe esse componente no layout raiz para limitar a fronteira do client a este módulo e aos imports dele.

Veja a [Referência da API](/docs/app/api-reference/functions/use-report-web-vitals) para mais informações.

</AppOnly>

## Web Vitals \{#web-vitals}

[Web Vitals](https://web.dev/vitals/) é um conjunto de métricas úteis que buscam capturar a experiência do usuário em uma página web. As seguintes Web Vitals estão incluídas:

- [Tempo até o primeiro byte](https://developer.mozilla.org/docs/Glossary/Time_to_first_byte) (TTFB)
- [Primeira pintura com conteúdo](https://developer.mozilla.org/docs/Glossary/First_contentful_paint) (FCP)
- [Maior pintura com conteúdo](https://web.dev/lcp/) (LCP)
- [Mudança cumulativa de layout](https://web.dev/cls/) (CLS)
- [Interação até a próxima pintura](https://web.dev/inp/) (INP)

Você pode tratar todos os resultados dessas métricas usando a propriedade `name`.

<PagesOnly>

```jsx filename="pages/_app.js"
import { useReportWebVitals } from 'next/web-vitals'

function MyApp({ Component, pageProps }) {
  useReportWebVitals((metric) => {
    switch (metric.name) {
      case 'FCP': {
        // handle FCP results
      }
      case 'LCP': {
        // handle LCP results
      }
      // ...
    }
  })

  return <Component {...pageProps} />
}
```

</PagesOnly>

## Métricas personalizadas \{#custom-metrics}

Além das métricas principais listadas acima, existem algumas métricas personalizadas adicionais que medem o tempo que a página leva para fazer a hydration e renderizar:

- `Next.js-hydration`: tempo que a página leva para começar e terminar a hydration (em ms)
- `Next.js-route-change-to-render`: tempo que a página leva para começar a renderizar após uma mudança de rota (em ms)
- `Next.js-render`: tempo que a página leva para terminar a renderização após uma mudança de rota (em ms)

Você pode tratar os resultados dessas métricas separadamente:

```js
export function reportWebVitals(metric) {
  switch (metric.name) {
    case 'Next.js-hydration':
      // handle hydration results
      break
    case 'Next.js-route-change-to-render':
      // handle route-change to render results
      break
    case 'Next.js-render':
      // handle render results
      break
    default:
      break
  }
}
```

Essas métricas funcionam em todos os navegadores que têm suporte à [User Timing API](https://caniuse.com/#feat=user-timing).

</PagesOnly>

## Enviando resultados para sistemas externos \{#sending-results-to-external-systems}

Você pode enviar os resultados para qualquer endpoint, para medir e acompanhar o desempenho real dos usuários no seu site. Por exemplo:

```js
useReportWebVitals((metric) => {
  const body = JSON.stringify(metric)
  const url = 'https://example.com/analytics'

  // Use `navigator.sendBeacon()` if available, falling back to `fetch()`.
  if (navigator.sendBeacon) {
    navigator.sendBeacon(url, body)
  } else {
    fetch(url, { body, method: 'POST', keepalive: true })
  }
})
```

> **Bom saber:** se você usa o [Google Analytics](https://analytics.google.com/analytics/web/), usar o valor `id` permite montar distribuições das métricas manualmente (para calcular percentis, etc.)

> ```js
> useReportWebVitals((metric) => {
>   // Use `window.gtag` if you initialized Google Analytics as this example:
>   // https://github.com/vercel/next.js/blob/canary/examples/with-google-analytics
>   window.gtag('event', metric.name, {
>     value: Math.round(
>       metric.name === 'CLS' ? metric.value * 1000 : metric.value
>     ), // values must be integers
>     event_label: metric.id, // id unique to current page load
>     non_interaction: true, // avoids affecting bounce rate.
>   })
> })
> ```
>
> Leia mais sobre [envio de resultados para o Google Analytics](https://github.com/GoogleChrome/web-vitals#send-the-results-to-google-analytics).
