O [Model Context Protocol (MCP)](https://modelcontextprotocol.io) é um padrão aberto que permite que agentes de IA e assistentes de código interajam com seus apps por meio de uma interface única e compartilhada.

No Next.js 16 e versões posteriores, o dev server expõe um endpoint MCP em `/_next/mcp`. Ele dá aos agentes de código a visão do app em execução sobre erros, rotas, logs e problemas de compilação. Para conectar seu cliente de agente a ele, instale o pacote [`next-devtools-mcp`](https://www.npmjs.com/package/next-devtools-mcp).

Skills como [`next-dev-loop`](/docs/app/guides/ai-agents#next-dev-loop) chamam `/_next/mcp` diretamente, então funcionam sem essa configuração.

## Primeiros passos \{#getting-started}

Instale o `next-devtools-mcp` para os agentes de código da sua máquina com o [`add-mcp`](https://www.npmjs.com/package/add-mcp):

```bash filename="Terminal"
npx add-mcp next-devtools-mcp@latest
```

Ou adicione-o ao arquivo `.mcp.json` na raiz do seu projeto:

```json filename=".mcp.json"
{
  "mcpServers": {
    "next-devtools": {
      "command": "npx",
      "args": ["-y", "next-devtools-mcp@latest"]
    }
  }
}
```

Ao iniciar seu dev server, o `next-devtools-mcp` descobre a instância do Next.js em execução e se conecta a ela. Para a configuração específica de cada cliente, veja o [repositório do next-devtools-mcp](https://github.com/vercel/next-devtools-mcp).

## Recursos \{#capabilities}

O `next-devtools-mcp` conecta seu cliente de agente ao dev server do Next.js. Ele oferece aos agentes estas ferramentas:

- **`nextjs_index`**: Descobre os dev servers do Next.js em execução e lista as ferramentas de runtime que cada um expõe.
- **`nextjs_call`**: Chama uma ferramenta de runtime em um dev server descoberto.
- **`nextjs_docs`**: Aponta o agente para a documentação da mesma versão do Next.js instalada no projeto, em `node_modules/next/dist/docs/`.
- **`browser_eval`**: Aponta o agente para a CLI do [`agent-browser`](https://github.com/vercel-labs/agent-browser), para verificar páginas em um navegador real.

`nextjs_docs` e `browser_eval` não fazem o trabalho sozinhos. Eles dizem ao agente onde estão os docs ou como rodar a CLI, e o agente os usa diretamente.

### Ferramentas de runtime \{#runtime-tools}

Por meio do `nextjs_call`, os agentes podem usar as ferramentas que o dev server do Next.js expõe em `/_next/mcp`:

- **`get_errors`**: Obtém o estado atual de erros, incluindo erros globais do Next.js, como validação do `next.config`, erros de runtime no navegador e erros de build com stack traces mapeados para o código-fonte.
- **`get_logs`**: Obtém o caminho do arquivo de log de desenvolvimento, que contém os logs do console do navegador e a saída do servidor.
- **`get_page_metadata`**: Obtém metadados de runtime sobre o que contribui para a renderização da página atual. Exige que a página esteja aberta em um navegador.
- **`get_project_metadata`**: Obtém o caminho do projeto e a URL do dev server.
- **`get_routes`**: Obtém todas as rotas que se tornarão pontos de entrada, varrendo o sistema de arquivos. Retorna as rotas agrupadas por tipo de router (`appRouter`, `pagesRouter`). Segmentos dinâmicos aparecem como padrões `[param]` ou `[...slug]`.
- **`get_server_action_by_id`**: Busca uma Server Action pelo ID para encontrar seu arquivo de origem e o nome da exportação.
- **`get_compilation_issues`**: Monta o grafo de módulos de todas as rotas e retorna problemas de compilação, como erros de resolução, módulos ausentes e erros de transformação. Não exige uma sessão de navegador. Somente com Turbopack.
- **`compile_route`**: Compila uma rota específica sem fazer uma requisição HTTP para ela. Aceita um `routeSpecifier` (por exemplo, `/blog/[slug]`, como retornado por `get_routes`) ou um `path` (por exemplo, `/blog/hello-world`), que é resolvido para a rota correspondente. Retorna os problemas de compilação da rota. Somente com Turbopack.
- **`get_request_insights`**: Obtém as linhas do tempo de requisições recentes do App Router, os fetches do servidor e o comportamento do cache capturados pelo gravador de spans local. Exige `experimental.requestInsights`.

Com as ferramentas de compilação, os agentes podem verificar se o código compila no dev server em execução, em vez de rodar `next build` enquanto ainda estão editando.

## Fluxo de trabalho de desenvolvimento \{#development-workflow}

1. Inicie o dev server do Next.js:

```bash package="pnpm"
pnpm dev
```

```bash package="npm"
npm run dev
```

```bash package="yarn"
yarn dev
```

```bash package="bun"
bun dev
```

2. Seu agente de código se conecta à instância do Next.js em execução por meio do `next-devtools-mcp`.

3. Abra no navegador as páginas em que você está trabalhando. Ferramentas como `get_errors` e `get_page_metadata` leem das sessões ativas do navegador.

4. Pergunte ao seu agente sobre o app em execução, como nos exemplos abaixo.

## Exemplos \{#examples}

### Detecção e diagnóstico de erros \{#error-detection-and-diagnosis}

Pergunte ao seu agente sobre erros no app em execução:

```prompt
What errors are currently in my application?
```

O agente vai:

- Descobrir o dev server em execução com `nextjs_index`
- Chamar `get_errors` por meio do `nextjs_call` para obter os erros atuais
- Analisar os erros e sugerir correções

### Conceitos e boas práticas \{#concepts-and-best-practices}

Faça perguntas conceituais:

```prompt
When should I use 'use client' in the App Router?
```

O agente lê a documentação da mesma versão do Next.js instalada no seu projeto e responde com exemplos do seu código.

## Como funciona \{#how-it-works}

O dev server do Next.js 16+ roda um endpoint MCP integrado em `/_next/mcp`. O pacote `next-devtools-mcp` descobre esses endpoints e se comunica com eles, para que possa:

- Conectar-se a várias instâncias do Next.js em portas diferentes
- Encaminhar as chamadas de ferramentas para o dev server certo
- Oferecer aos agentes um único conjunto de ferramentas para todas as instâncias

Agentes que se conectam pelo `next-devtools-mcp` usam a mesma configuração em projetos e versões diferentes do Next.js.

O endpoint vem habilitado por padrão. Para desativá-lo, defina `experimental.mcpServer` como `false` no `next.config`.

## Solução de problemas \{#troubleshooting}

### Servidor MCP não conecta \{#mcp-server-not-connecting}

- Use o Next.js 16 ou uma versão posterior
- Confira se o `next-devtools-mcp` está configurado no seu cliente de agente, por exemplo, no `.mcp.json`
- Verifique se `experimental.mcpServer` não está definido como `false` no `next.config`
- Inicie seu dev server com `npm run dev` ou reinicie-o, caso já estivesse rodando
- Confira se seu agente de código carregou a configuração do servidor MCP
