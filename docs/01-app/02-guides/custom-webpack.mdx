Por padrão, `--webpack` usa a versão do webpack empacotada com o Next.js. Para usar o webpack instalado no seu app, instale o webpack no app e passe `--custom-webpack` para `next dev` ou `next build`. Execute os comandos de desenvolvimento e de produção separadamente; o `next dev` continua rodando até ser interrompido:

```bash package="pnpm"
pnpm add -D webpack@^5.98.0
pnpm next dev --custom-webpack
pnpm next build --custom-webpack
```

```bash package="npm"
npm install -D webpack@^5.98.0
npx next dev --custom-webpack
npx next build --custom-webpack
```

```bash package="yarn"
yarn add -D webpack@^5.98.0
yarn next dev --custom-webpack
yarn next build --custom-webpack
```

```bash package="bun"
bun add -D webpack@^5.98.0
bunx next dev --custom-webpack
bunx next build --custom-webpack
```

**Use uma versão personalizada do webpack por sua conta e risco.** O Next.js não valida a versão do webpack instalada, e a compatibilidade com outras versões não é garantida. Os exemplos usam `^5.98.0`; este recurso é testado com o webpack 5.98.0 e 5.111.0.

Execute o comando de instalação no diretório do seu app. A versão personalizada fica disponível quando o Next.js avalia o `next.config.js`, então sua configuração do webpack e seus plugins podem importá-la. Se o webpack não estiver instalado no app, o `--custom-webpack` informa como instalá-lo.

**pnpm com hoisting restrito:** o Next.js resolve o webpack diretamente do seu app, mesmo quando o pnpm não faz o hoisting dele. No entanto, plugins personalizados do webpack ou outras ferramentas do workspace podem resolver o webpack a partir dos próprios locais de pacote. Se elas não conseguirem encontrá-lo porque você restringiu o [hoisting](https://pnpm.io/settings/node-modules#hoistpattern) do pnpm, adicione `webpack` ao `hoistPattern` existente no `pnpm-workspace.yaml` da raiz do workspace:

```yaml filename="pnpm-workspace.yaml"
hoistPattern:
  - '*eslint*' # Example existing pattern; keep your own patterns.
  - webpack
```

Mantenha quaisquer outros padrões que seu projeto já usa. Se você usa o `hoistPattern` padrão do pnpm (`['*']`), não precisa dessa configuração. Se você desativou o hoisting por completo com `hoist: false`, ative-o antes de usar o `hoistPattern`. Veja as [configurações de node-modules do pnpm](https://pnpm.io/settings/node-modules) para mais detalhes.
