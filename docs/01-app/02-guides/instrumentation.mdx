Instrumentação é o processo de usar código para integrar ferramentas de monitoramento e de logs ao seu app. Isso permite acompanhar o desempenho e o comportamento do seu app e depurar problemas em produção.

## Convenção \{#convention}

Para configurar a instrumentação, crie um arquivo `instrumentation.ts|js` no **diretório raiz** do seu projeto (ou dentro da pasta [`src`](/docs/app/api-reference/file-conventions/src-folder), se você usar uma).

Depois, exporte uma função `register` no arquivo. Essa função será chamada **uma vez** quando uma nova instância do servidor Next.js for iniciada, e precisa terminar antes de o servidor estar pronto para atender requisições.

Por exemplo, para usar o Next.js com o [OpenTelemetry](https://opentelemetry.io/) e o [@vercel/otel](https://vercel.com/docs/tracing/instrumentation):

```ts filename="instrumentation.ts" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

```js filename="instrumentation.js" switcher
import { registerOTel } from '@vercel/otel'

export function register() {
  registerOTel('next-app')
}
```

Veja o [exemplo do Next.js com OpenTelemetry](https://github.com/vercel/next.js/tree/canary/examples/with-opentelemetry) para uma implementação completa.

> **Bom saber**:
>
> - O arquivo `instrumentation` deve ficar na raiz do projeto, e não dentro das pastas `app` ou `pages`. Se você usar a pasta `src`, coloque o arquivo dentro de `src`, junto de `pages` e `app`.
> - Se você usar a opção de configuração [`pageExtensions`](/docs/app/api-reference/config/next-config-js/pageExtensions) para adicionar um sufixo, também precisará atualizar o nome do arquivo `instrumentation` para corresponder.

## Exemplos \{#examples}

### Importando arquivos com efeitos colaterais \{#importing-files-with-side-effects}

Às vezes, pode ser útil importar um arquivo no seu código por causa dos efeitos colaterais que ele causa. Por exemplo, você pode importar um arquivo que define um conjunto de variáveis globais, mas nunca usa explicitamente o arquivo importado no seu código. Você ainda terá acesso às variáveis globais que o pacote declarou.

Recomendamos importar arquivos usando a sintaxe `import` do JavaScript dentro da sua função `register`. O exemplo a seguir demonstra um uso básico de `import` em uma função `register`:

```ts filename="instrumentation.ts" switcher
export async function register() {
  await import('package-with-side-effect')
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  await import('package-with-side-effect')
}
```

> **Bom saber:**
>
> Recomendamos importar o arquivo dentro da função `register`, e não no topo do arquivo. Assim, você pode concentrar todos os seus efeitos colaterais em um só lugar do código e evitar consequências não intencionais de importar globalmente no topo do arquivo.

### Importando código específico de runtime \{#importing-runtime-specific-code}

O Next.js chama `register` em todos os ambientes, então é importante importar condicionalmente qualquer código que não funcione em runtimes específicos (por exemplo, [Edge ou Node.js](/docs/app/api-reference/edge)). Você pode usar a variável de ambiente `NEXT_RUNTIME` para descobrir o ambiente atual:

```ts filename="instrumentation.ts" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation-node')
  }

  if (process.env.NEXT_RUNTIME === 'edge') {
    await import('./instrumentation-edge')
  }
}
```

```js filename="instrumentation.js" switcher
export async function register() {
  if (process.env.NEXT_RUNTIME === 'nodejs') {
    await import('./instrumentation-node')
  }

  if (process.env.NEXT_RUNTIME === 'edge') {
    await import('./instrumentation-edge')
  }
}
```
