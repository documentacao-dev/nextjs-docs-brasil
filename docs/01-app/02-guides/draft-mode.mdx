O **Draft Mode** permite que editores vejam como conteúdo em rascunho ou em andamento será renderizado no seu site, sem esperar pela revalidação. Enquanto um editor está no Draft Mode, o conteúdo em cache ou prerendered é ignorado e buscado diretamente nas fontes de origem. Os outros visitantes continuam vendo a versão em cache ou prerendered da página.

Seu código de busca de dados não precisa mudar se o seu CMS serve conteúdo em rascunho e publicado pela mesma URL. Caso contrário, veja [Quando seu CMS usa um endpoint de rascunho separado](#when-your-cms-uses-a-separate-draft-endpoint).

## O que o Draft Mode faz \{#what-draft-mode-does}

Quando o Draft Mode está habilitado para uma requisição:

- Chamadas de `fetch()` ignoram o cache de fetch do Next.js e vão direto à rede.
- Componentes e funções dentro de [`'use cache'`](/docs/app/api-reference/directives/use-cache) são reexecutados a cada requisição, e os resultados deles não são salvos no cache.
- As leituras e gravações do [`unstable_cache`](/docs/app/api-reference/functions/unstable_cache) também são ignoradas da mesma forma.
- A página fica fora do cache de resposta do ISR e é servida com `Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate`.

O efeito vale tanto se a página for gerada estaticamente, servida do cache ou revalidada pelo ISR.

## O que este guia aborda \{#what-this-guide-covers}

Este guia pressupõe que:

- Seu CMS headless aceita URLs de preview configuráveis (a maioria aceita).
- O CMS abre uma URL como `/api/draft?secret=XXX&slug=/posts/foo` em uma nova aba quando um editor clica em "Preview". O secret é um token compartilhado; o slug é o caminho que será visualizado.
- Seu app Next.js valida o secret, habilita o Draft Mode e redireciona para o slug.

Com esse contrato em mente, o restante deste guia percorre:

1. Criar um Route Handler que habilita o Draft Mode definindo um cookie.
2. Proteger esse handler com o secret compartilhado e o slug vindos do CMS.
3. Renderizar páginas que leem o rascunho mais recente.
4. Exibir um banner de visualização com um formulário de saída.

Depois, dependendo da sua configuração:

- [Draft Mode com Cache Components](#draft-mode-with-cache-components) para exibir o estado de visualização a partir de um limite `'use cache'`.
- [Quando seu CMS usa um endpoint de rascunho separado](#when-your-cms-uses-a-separate-draft-endpoint) para escolher a URL de busca de acordo com `isEnabled`.

> **Bom saber:** `GET` deve ser um método seguro, somente leitura. Operações que afetam requisições futuras, como habilitar o Draft Mode por meio de um cookie, devem usar `POST`. O handler de entrada usa `GET` porque estamos supondo uma integração de preview com CMS: o CMS abre a URL em uma nova aba do navegador, o que é uma requisição `GET`. O fluxo de saída do Passo 4 usa `POST` (por meio de uma [Server Action](/docs/app/getting-started/mutating-data) ou de um Route Handler `POST`).

## Passo 1: criar um Route Handler \{#step-1-create-a-route-handler}

Crie um [Route Handler](/docs/app/api-reference/file-conventions/route) que define o cookie do Draft Mode. Ele pode ter qualquer nome, por exemplo, `app/api/draft/route.ts`.

```ts filename="app/api/draft/route.ts" switcher
import { draftMode } from 'next/headers'

export async function GET(request: Request) {
  const draft = await draftMode()
  draft.enable()
  return new Response('Draft mode is enabled')
}
```

```js filename="app/api/draft/route.js" switcher
import { draftMode } from 'next/headers'

export async function GET(request) {
  const draft = await draftMode()
  draft.enable()
  return new Response('Draft mode is enabled')
}
```

`draft.enable()` define um cookie chamado `__prerender_bypass`. As requisições seguintes que carregam esse cookie ignoram todas as camadas de cache listadas acima.

Você pode testar isso manualmente acessando `/api/draft` e observando as ferramentas de desenvolvedor do navegador. Repare no header de resposta `Set-Cookie`.

Do jeito que está, o handler é público: qualquer pessoa que acessar `/api/draft` habilita o Draft Mode para si mesma. O Passo 2 fecha essa brecha com um secret compartilhado, para que apenas o seu CMS consiga chamá-lo.

## Passo 2: acesse o Route Handler a partir do seu CMS headless \{#step-2-access-the-route-handler-from-your-headless-cms}

> Estes passos pressupõem que o CMS headless que você usa aceita definir **URLs de rascunho personalizadas**. Se não aceitar, você ainda pode usar este método para proteger suas URLs de rascunho, mas precisará montar e acessar a URL de rascunho manualmente. Os passos específicos variam conforme o CMS headless que você usa.

Para acessar o Route Handler com segurança a partir do seu CMS headless:

1. Crie uma **string de token secreto** usando o gerador de tokens de sua preferência. Esse secret é conhecido apenas pelo seu app Next.js e pelo seu CMS headless.
2. Se o seu CMS headless aceitar URLs de rascunho personalizadas, especifique uma URL de rascunho (isto pressupõe que o seu Route Handler está em `app/api/draft/route.ts`). Por exemplo:

```bash filename="Terminal"
https://<your-site>/api/draft?secret=<token>&slug=<path>
```

> - `<your-site>` deve ser o domínio do seu deploy.
> - `<token>` deve ser substituído pelo secret que você gerou.
> - `<path>` deve ser o caminho da página que você quer visualizar. Se quiser visualizar `/posts/one`, use `&slug=/posts/one`.
>
> O seu CMS headless pode permitir incluir uma variável na URL de rascunho, para que `<path>` seja definido dinamicamente com base nos dados do CMS, assim: `&slug=/posts/{entry.fields.slug}`

3. No seu Route Handler, verifique se o secret corresponde e se o parâmetro `slug` existe (caso contrário, a requisição deve falhar), chame `draft.enable()` para definir o cookie e depois redirecione o navegador para o caminho especificado em `slug`:

```ts filename="app/api/draft/route.ts" switcher
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url)
  const secret = searchParams.get('secret')
  const slug = searchParams.get('slug')

  // This secret should only be known to this Route Handler and the CMS
  if (secret !== 'MY_SECRET_TOKEN' || !slug) {
    return new Response('Invalid token', { status: 401 })
  }

  // Verify the slug exists in the CMS before enabling Draft Mode
  const post = await getPostBySlug(slug)
  if (!post) {
    return new Response('Invalid slug', { status: 401 })
  }

  const draft = await draftMode()
  draft.enable()

  // Redirect to the path from the fetched post, not from searchParams,
  // to avoid open redirect vulnerabilities
  redirect(post.slug)
}
```

```js filename="app/api/draft/route.js" switcher
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

export async function GET(request) {
  const { searchParams } = new URL(request.url)
  const secret = searchParams.get('secret')
  const slug = searchParams.get('slug')

    return new Response('Invalid token', { status: 401 })
  }

    return new Response('Invalid slug', { status: 401 })
  }

```

Se der certo, o navegador é redirecionado para o caminho de destino com o cookie do Draft Mode definido.

## Passo 3: visualize o conteúdo em rascunho \{#step-3-preview-the-draft-content}

Como o Draft Mode ignora o cache automaticamente, sua página não precisa saber se o Draft Mode está ativo para receber conteúdo atualizado. Busque os dados como de costume:

```tsx filename="app/posts/[slug]/page.tsx" switcher
async function getPost(slug: string) {
  const res = await fetch(`https://cms.example.com/posts/${slug}`)
  return res.json()
}

export default async function Page({ params }: PageProps<'/posts/[slug]'>) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <main>
      <h1>{post.title}</h1>
      <article>{post.content}</article>
    </main>
  )
}
```

```jsx filename="app/posts/[slug]/page.js" switcher
async function getPost(slug) {
  const res = await fetch(`https://cms.example.com/posts/${slug}`)
  return res.json()
}

export default async function Page({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <main>
      <h1>{post.title}</h1>
      <article>{post.content}</article>
    </main>
  )
}
```

Quando o cookie do Draft Mode está presente, o `fetch` acima ignora o cache de fetch do Next.js e vai ao seu CMS buscar o rascunho atual. Quando não está, a mesma requisição pode ser servida pelo cache, como de costume.

Se o seu CMS usar uma URL diferente para rascunhos em vez de servi-los pelo mesmo endpoint, veja [Quando seu CMS usa um endpoint de rascunho separado](#when-your-cms-uses-a-separate-draft-endpoint).

## Passo 4: exiba um indicador de visualização \{#step-4-show-a-preview-indicator}

`isEnabled` é mais útil como sinal para o editor: um banner que confirma que ele está vendo conteúdo em rascunho, além de uma forma de sair. Renderize um indicador no seu layout raiz para que ele apareça em todas as páginas de visualização.

```tsx filename="app/preview-banner.tsx" switcher
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

async function exitPreview() {
  'use server'
  const draft = await draftMode()
  draft.disable()
  redirect('/')
}

export async function PreviewBanner() {
  const { isEnabled } = await draftMode()
  if (!isEnabled) return null

  return (
    <aside role="status">
      Preview mode is on.{' '}
      <form action={exitPreview}>
        <button type="submit">Exit preview</button>
      </form>
    </aside>
  )
}
```

```jsx filename="app/preview-banner.js" switcher
import { draftMode } from 'next/headers'
import { redirect } from 'next/navigation'

async function exitPreview() {
  'use server'
  const draft = await draftMode()
  draft.disable()
  redirect('/')
}

export async function PreviewBanner() {
  const { isEnabled } = await draftMode()
  if (!isEnabled) return null

  return (
    <aside role="status">
      Preview mode is on.{' '}
      <form action={exitPreview}>
        <button type="submit">Exit preview</button>
      </form>
    </aside>
  )
}
```

Sair do Draft Mode também funciona com um Route Handler `GET`, mas um `POST` é semanticamente mais correto, por exemplo, por meio de um formulário enviado por uma [Server Action](/docs/app/getting-started/mutating-data) ou para um Route Handler `POST`.

Se você usar um Route Handler `GET`, acione-o a partir de um `<form method="GET">` em vez de um [`<Link>`](/docs/app/api-reference/components/link). O Next.js faz prefetch dos componentes `<Link>` por padrão, o que limparia o cookie antes de o editor clicar. Formulários não passam por prefetch, independentemente do método.

## Draft Mode com Cache Components \{#draft-mode-with-cache-components}

Você pode ler `isEnabled` dentro de um escopo [`'use cache'`](/docs/app/api-reference/directives/use-cache) para renderizar um indicador de visualização a partir de um componente em cache. O bypass do cache continua valendo, então o componente é reexecutado com dados atualizados a cada requisição de rascunho.

```tsx filename="app/posts/[slug]/page.tsx" switcher
import { draftMode } from 'next/headers'

async function Post({ slug }: { slug: string }) {
  'use cache'

  const post = await fetch(`https://cms.example.com/posts/${slug}`).then((r) =>
    r.json()
  )
  const { isEnabled } = await draftMode()

  return (
    <article>
      {isEnabled && <p role="status">Draft preview</p>}
      <h1>{post.title}</h1>
      <div>{post.content}</div>
    </article>
  )
}
```

```jsx filename="app/posts/[slug]/page.js" switcher
import { draftMode } from 'next/headers'

async function Post({ slug }) {
  'use cache'

  const post = await fetch(`https://cms.example.com/posts/${slug}`).then((r) =>
    r.json()
  )
  const { isEnabled } = await draftMode()

  return (
    <article>
      {isEnabled && <p role="status">Draft preview</p>}
      <h1>{post.title}</h1>
      <div>{post.content}</div>
    </article>
  )
}
```

> **Bom saber:** `draftMode().enable()` e `draftMode().disable()` não podem ser chamados dentro de um escopo de diretiva de cache; alterne o Draft Mode a partir de um [Route Handler](/docs/app/api-reference/file-conventions/route) ou de uma [Server Action](/docs/app/getting-started/mutating-data).

## Quando seu CMS usa um endpoint de rascunho separado \{#when-your-cms-uses-a-separate-draft-endpoint}

Se o seu CMS expõe o conteúdo em rascunho em outra URL ou exige credenciais diferentes, faça a busca variar de acordo com `isEnabled`:

```tsx filename="app/posts/[slug]/page.tsx" switcher
import { draftMode } from 'next/headers'

async function getPost(slug: string) {
  const { isEnabled } = await draftMode()
  const baseUrl = isEnabled
    ? 'https://cms.example.com/preview'
    : 'https://cms.example.com/published'

  const res = await fetch(`${baseUrl}/posts/${slug}`)
  return res.json()
}
```

```jsx filename="app/posts/[slug]/page.js" switcher
import { draftMode } from 'next/headers'

async function getPost(slug) {
  const { isEnabled } = await draftMode()
  const baseUrl = isEnabled
    ? 'https://cms.example.com/preview'
    : 'https://cms.example.com/published'

  const res = await fetch(`${baseUrl}/posts/${slug}`)
  return res.json()
}
```

O bypass do cache continua valendo para os dois ramos; a bifurcação só escolhe de onde ler.
