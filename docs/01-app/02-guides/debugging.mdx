Esta documentação explica como depurar o código de frontend e backend do seu Next.js, com suporte completo a source maps, usando o [depurador do VS Code](https://code.visualstudio.com/docs/editor/debugging), o [Chrome DevTools](https://developers.google.com/web/tools/chrome-devtools) ou o [Firefox DevTools](https://firefox-source-docs.mozilla.org/devtools-user/).

Qualquer depurador que consiga se conectar ao Node.js também pode ser usado para depurar um app Next.js. Você encontra mais detalhes no [Guia de depuração](https://nodejs.org/learn/getting-started/debugging/) do Node.js.

## Depurando com o VS Code \{#debugging-with-vs-code}

Crie um arquivo chamado `.vscode/launch.json` na raiz do seu projeto com o seguinte conteúdo:

```json filename="launch.json"
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Next.js: debug server-side",
      "type": "node-terminal",
      "request": "launch",
      "command": "npm run dev -- --inspect"
    },
    {
      "name": "Next.js: debug client-side",
      "type": "chrome",
      "request": "launch",
      "url": "http://localhost:3000"
    },
    {
      "name": "Next.js: debug client-side (Firefox)",
      "type": "firefox",
      "request": "launch",
      "url": "http://localhost:3000",
      "reAttach": true,
      "pathMappings": [
        {
          "url": "webpack://_N_E",
          "path": "${workspaceFolder}"
        }
      ]
    },
    {
      "name": "Next.js: debug full stack",
      "type": "node",
      "request": "launch",
      "program": "${workspaceFolder}/node_modules/next/dist/bin/next",
      "runtimeArgs": ["--inspect"],
      "skipFiles": ["<node_internals>/**"],
      "serverReadyAction": {
        "action": "debugWithEdge",
        "killOnServerStop": true,
        "pattern": "- Local:.+(https?://.+)",
        "uriFormat": "%s",
        "webRoot": "${workspaceFolder}"
      }
    }
  ]
}
```

> **Nota**: Para usar a depuração do Firefox no VS Code, você precisa instalar a [extensão Firefox Debugger](https://marketplace.visualstudio.com/items?itemName=firefox-devtools.vscode-firefox-debug).

`npm run dev` pode ser substituído por `yarn dev`, se você usa o Yarn, ou por `pnpm dev`, se você usa o pnpm.

Na configuração "Next.js: debug full stack", `serverReadyAction.action` especifica qual navegador abrir quando o servidor estiver pronto. `debugWithEdge` significa abrir o navegador Edge. Se você usa o Chrome, troque esse valor para `debugWithChrome`.

Se você [mudar a porta](/docs/pages/api-reference/cli/next#next-dev-options) em que sua aplicação inicia, substitua o `3000` em `http://localhost:3000` pela porta que você está usando.

Se você executa o Next.js a partir de um diretório diferente da raiz (por exemplo, usando o Turborepo), precisa adicionar `cwd` às tarefas de depuração do servidor e do full stack. Por exemplo, `"cwd": "${workspaceFolder}/apps/web"`.

Agora, vá para o painel Debug (`Ctrl+Shift+D` no Windows/Linux, `⇧+⌘+D` no macOS), selecione uma configuração de launch e pressione `F5` ou selecione **Debug: Start Debugging** na Paleta de comandos para iniciar a sessão de depuração.

## Usando o depurador no Jetbrains WebStorm \{#using-the-debugger-in-jetbrains-webstorm}

Clique no menu suspenso que lista a configuração de runtime e clique em `Edit Configurations...`. Crie uma configuração de depuração `JavaScript Debug` com `http://localhost:3000` como URL. Personalize como preferir (por exemplo, Browser para depuração, salvar como arquivo do projeto) e clique em `OK`. Execute essa configuração de depuração e o navegador selecionado deve abrir automaticamente. Neste ponto, você terá 2 aplicações em modo de depuração: a aplicação Node.js do Next.js e a aplicação do cliente/navegador.

## Depurando com as DevTools do navegador \{#debugging-with-browser-devtools}

### Código no cliente \{#client-side-code}

Inicie seu dev server normalmente, executando `next dev`, `npm run dev` ou `yarn dev`. Quando o servidor iniciar, abra `http://localhost:3000` (ou a sua URL alternativa) no navegador de sua preferência.

No Chrome:

- Abra as Developer Tools do Chrome (`Ctrl+Shift+J` no Windows/Linux, `⌥+⌘+I` no macOS)
- Vá para a aba **Sources**

No Firefox:

- Abra as Developer Tools do Firefox (`Ctrl+Shift+I` no Windows/Linux, `⌥+⌘+I` no macOS)
- Vá para a aba **Debugger**

Em qualquer um dos navegadores, sempre que o seu código do cliente chegar a uma instrução [`debugger`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Statements/debugger), a execução do código será pausada e esse arquivo aparecerá na área de depuração. Você também pode buscar arquivos para definir breakpoints manualmente:

- No Chrome: pressione `Ctrl+P` no Windows/Linux ou `⌘+P` no macOS
- No Firefox: pressione `Ctrl+P` no Windows/Linux ou `⌘+P` no macOS, ou use a árvore de arquivos no painel da esquerda

Observe que, ao buscar, seus arquivos de código-fonte terão caminhos começando com `webpack://_N_E/./`.

### React Developer Tools \{#react-developer-tools}

Para depurar especificamente o React, instale a extensão de navegador [React Developer Tools](https://react.dev/learn/react-developer-tools). Esta ferramenta essencial ajuda você a:

- Inspecionar componentes React
- Editar props e estado
- Identificar problemas de performance

### Código no servidor \{#server-side-code}

Para depurar o código do servidor do Next.js com as DevTools do navegador, você precisa passar a flag `--inspect`:

```bash package="pnpm"
pnpm dev --inspect
```

```bash package="npm"
npm run dev -- --inspect
```

```bash package="yarn"
yarn dev --inspect
```

```bash package="bun"
bun run dev --inspect
```

O valor de `--inspect` é repassado para o processo Node.js subjacente. Veja a [documentação do `--inspect` para casos de uso avançados](https://nodejs.org/api/cli.html#--inspecthostport).

> **Bom saber**: Use `--inspect=0.0.0.0` para permitir acesso remoto para depuração fora do localhost, por exemplo, ao rodar o app em um container Docker.

Iniciar o servidor do Next.js com a flag `--inspect` vai gerar uma saída parecida com esta:

```bash filename="Terminal"
Debugger listening on ws://127.0.0.1:9229/0cf90313-350d-4466-a748-cd60f4e47c95
For help, see: https://nodejs.org/learn/getting-started/debugging
ready - started server on 0.0.0.0:3000, url: http://localhost:3000
```

No Chrome:

1. Abra uma nova aba e acesse `chrome://inspect`
1. Procure a sua aplicação Next.js na seção **Remote Target**
1. Clique em **inspect** para abrir uma janela separada das DevTools
1. Vá para a aba **Sources**

No Firefox:

1. Abra uma nova aba e acesse `about:debugging`
1. Clique em **This Firefox** na barra lateral esquerda
1. Em **Remote Targets**, encontre a sua aplicação Next.js
1. Clique em **Inspect** para abrir o depurador
1. Vá para a aba **Debugger**

A depuração do código do servidor funciona de forma semelhante à depuração do cliente. Ao buscar arquivos (`Ctrl+P`/`⌘+P`), seus arquivos de código-fonte terão caminhos começando com `webpack://{application-name}/./` (onde `{application-name}` será substituído pelo nome da sua aplicação, de acordo com o arquivo `package.json`).

Para usar `--inspect-brk` ou `--inspect-wait`, é preciso especificar o `NODE_OPTIONS`. Por exemplo: `NODE_OPTIONS=--inspect-brk next dev`.

### Inspecionando erros do servidor com as DevTools do navegador \{#inspect-server-errors-with-browser-devtools}

Quando você encontra um erro, inspecionar o código-fonte pode ajudar a rastrear a causa raiz.

O Next.js exibe um ícone do Node.js abaixo do indicador de versão do Next.js na sobreposição de erro. Ao clicar nesse ícone, a URL das DevTools é copiada para a área de transferência. Você pode abrir uma nova aba do navegador com essa URL para inspecionar o processo do servidor do Next.js.

### Depurando no Windows \{#debugging-on-windows}

Confira se o Windows Defender está desativado na sua máquina. Esse serviço externo verifica _cada leitura de arquivo_, o que, segundo relatos, aumenta muito o tempo do Fast Refresh com `next dev`. Trata-se de um problema conhecido, que não é relacionado ao Next.js, mas que afeta o desenvolvimento com Next.js.
