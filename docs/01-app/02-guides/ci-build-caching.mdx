---
title: Como configurar o cache de build em Integração Contínua (CI)
nav_title: Cache de build em CI
description: Saiba como configurar o CI para armazenar em cache os builds do Next.js
---

Para melhorar a performance do build, o Next.js salva um cache em `.next/cache` que é compartilhado entre os builds.

Para aproveitar esse cache em ambientes de Integração Contínua (CI), o seu workflow de CI precisa estar configurado para manter o cache corretamente entre os builds.

> Se o seu CI não estiver configurado para manter `.next/cache` entre os builds, você pode ver o erro [No Cache Detected](/docs/messages/no-cache).

Veja a seguir alguns exemplos de configuração de cache para provedores de CI comuns:

## Vercel \{#vercel}

O cache do Next.js já é configurado automaticamente para você. Não é preciso fazer nada. Se você usa o Turborepo na Vercel, [saiba mais aqui](https://vercel.com/docs/monorepos/turborepo).

## CircleCI \{#circleci}

Edite a etapa `save_cache` em `.circleci/config.yml` para incluir `.next/cache`:

```yaml
steps:
  - save_cache:
      key: dependency-cache-{{ checksum "yarn.lock" }}
      paths:
        - ./node_modules
        - ./.next/cache
```

Se você não tiver uma chave `save_cache`, siga a [documentação do CircleCI sobre como configurar o cache de build](https://circleci.com/docs/2.0/caching/).

## Travis CI \{#travis-ci}

Adicione ou mescle o seguinte no seu `.travis.yml`:

```yaml
cache:
  directories:
    - $HOME/.cache/yarn
    - node_modules
    - .next/cache
```

## GitLab CI \{#gitlab-ci}

Adicione ou mescle o seguinte no seu `.gitlab-ci.yml`:

```yaml
cache:
  key: ${CI_COMMIT_REF_SLUG}
  paths:
    - node_modules/
    - .next/cache/
```

## Netlify CI \{#netlify-ci}

Use [Netlify Plugins](https://www.netlify.com/products/build/plugins/) com o [`@netlify/plugin-nextjs`](https://www.npmjs.com/package/@netlify/plugin-nextjs).

## AWS CodeBuild \{#aws-codebuild}

Adicione (ou mescle) o seguinte no seu `buildspec.yml`:

```yaml
cache:
  paths:
    - 'node_modules/**/*' # Cache `node_modules` for faster `yarn` or `npm i`
    - '.next/cache/**/*' # Cache Next.js for faster application rebuilds
```

## GitHub Actions \{#github-actions}

Usando o [actions/cache](https://github.com/actions/cache) do GitHub, adicione a seguinte etapa no seu arquivo de workflow:

```yaml
uses: actions/cache@v4
with:
  # See here for caching with `yarn`, `bun` or other package managers https://github.com/actions/cache/blob/main/examples.md or you can leverage caching with actions/setup-node https://github.com/actions/setup-node
  path: |
    ~/.npm
    ${{ github.workspace }}/.next/cache
  # Generate a new cache whenever packages or source files change.
  key: ${{ runner.os }}-nextjs-${{ hashFiles('**/package-lock.json') }}-${{ hashFiles('**/*.js', '**/*.jsx', '**/*.ts', '**/*.tsx') }}
  # If source files changed but packages didn't, rebuild from a prior cache.
  restore-keys: |
    ${{ runner.os }}-nextjs-${{ hashFiles('**/package-lock.json') }}-
```

## Bitbucket Pipelines \{#bitbucket-pipelines}

Adicione ou mescle o seguinte no seu `bitbucket-pipelines.yml`, no nível mais alto (no mesmo nível de `pipelines`):

```yaml
definitions:
  caches:
    nextcache: .next/cache
```

Depois, referencie-o na seção `caches` do `step` do seu pipeline:

```yaml
- step:
    name: your_step_name
    caches:
      - node
      - nextcache
```

## Heroku \{#heroku}

Usando o [cache personalizado](https://devcenter.heroku.com/articles/nodejs-support#custom-caching) do Heroku, adicione um array `cacheDirectories` no package.json do nível raiz:

```javascript
"cacheDirectories": [".next/cache"]
```

## Azure Pipelines \{#azure-pipelines}

Usando a tarefa [Cache](https://docs.microsoft.com/en-us/azure/devops/pipelines/tasks/utility/cache) do Azure Pipelines, adicione a seguinte tarefa no seu arquivo yaml de pipeline, antes da tarefa que executa `next build`:

```yaml
- task: Cache@2
  displayName: 'Cache .next/cache'
  inputs:
    key: next | $(Agent.OS) | yarn.lock
    path: '$(System.DefaultWorkingDirectory)/.next/cache'
```

## Jenkins (Pipeline) \{#jenkins-pipeline}

Usando o plugin [Job Cacher](https://www.jenkins.io/doc/pipeline/steps/jobcacher/) do Jenkins, adicione a seguinte etapa de build no seu `Jenkinsfile`, no lugar onde você normalmente executaria `next build` ou `npm install`:

```yaml
stage("Restore npm packages") {
    steps {
        // Writes lock-file to cache based on the GIT_COMMIT hash
        writeFile file: "next-lock.cache", text: "$GIT_COMMIT"

        cache(caches: [
            arbitraryFileCache(
                path: "node_modules",
                includes: "**/*",
                cacheValidityDecidingFile: "package-lock.json"
            )
        ]) {
            sh "npm install"
        }
    }
}
stage("Build") {
    steps {
        // Writes lock-file to cache based on the GIT_COMMIT hash
        writeFile file: "next-lock.cache", text: "$GIT_COMMIT"

        cache(caches: [
            arbitraryFileCache(
                path: ".next/cache",
                includes: "**/*",
                cacheValidityDecidingFile: "next-lock.cache"
            )
        ]) {
            // aka `next build`
            sh "npm run build"
        }
    }
}
```
