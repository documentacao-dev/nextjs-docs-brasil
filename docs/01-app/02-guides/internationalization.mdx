O Next.js permite configurar o roteamento e a renderização de conteúdo para oferecer suporte a vários idiomas. Tornar seu site adaptável a diferentes locales inclui conteúdo traduzido (localização) e rotas internacionalizadas.

## Terminologia \{#terminology}

- **Locale:** um identificador para um conjunto de preferências de idioma e formatação. Normalmente inclui o idioma preferido do usuário e, possivelmente, sua região geográfica.
  - `en-US`: inglês falado nos Estados Unidos
  - `nl-NL`: holandês falado nos Países Baixos
  - `nl`: holandês, sem região específica

## Visão geral do roteamento \{#routing-overview}

Recomenda-se usar as preferências de idioma do usuário no navegador para selecionar qual locale usar. Quando o usuário altera o idioma preferido, o header `Accept-Language` enviado ao seu app também muda.

Por exemplo, usando as bibliotecas a seguir, você pode analisar uma `Request` recebida para decidir qual locale selecionar, com base nos `Headers`, nos locales que pretende oferecer e no locale padrão.

```js filename="proxy.js"
import { match } from '@formatjs/intl-localematcher'
import Negotiator from 'negotiator'

let headers = { 'accept-language': 'en-US,en;q=0.5' }
let languages = new Negotiator({ headers }).languages()
let locales = ['en-US', 'nl-NL', 'nl']
let defaultLocale = 'en-US'

match(languages, locales, defaultLocale) // -> 'en-US'
```

O roteamento pode ser internacionalizado por subcaminho (`/fr/products`) ou por domínio (`my-site.fr/products`). Com essas informações, agora você pode redirecionar o usuário com base no locale dentro do [Proxy](/docs/app/api-reference/file-conventions/proxy).

```js filename="proxy.js"
import { NextResponse } from "next/server";

let locales = ['en-US', 'nl-NL', 'nl']

// Get the preferred locale, similar to the above or using a library
function getLocale(request) { ... }

export function proxy(request) {
  // Check if there is any supported locale in the pathname
  const { pathname } = request.nextUrl
  const pathnameHasLocale = locales.some(
    (locale) => pathname.startsWith(`/${locale}/`) || pathname === `/${locale}`
  )

  if (pathnameHasLocale) return

  // Redirect if there is no locale
  const locale = getLocale(request)
  request.nextUrl.pathname = `/${locale}${pathname}`
  // e.g. incoming request is /products
  // The new URL is now /en-US/products
  return NextResponse.redirect(request.nextUrl)
}

export const config = {
  matcher: [
    // Skip all internal paths (_next)
    '/((?!_next).*)',
    // Optional: only run on root (/) URL
    // '/'
  ],
}
```

Por fim, garanta que todos os arquivos especiais dentro de `app/` estejam aninhados em `app/[lang]`. Isso permite que o roteador do Next.js trate dinamicamente os diferentes locales na rota e repasse o parâmetro `lang` para todos os layouts e páginas. Por exemplo:

```tsx filename="app/[lang]/page.tsx" switcher
// You now have access to the current locale
// e.g. /en-US/products -> `lang` is "en-US"
export default async function Page({ params }: PageProps<'/[lang]'>) {
  const { lang } = await params
  return ...
}
```

```jsx filename="app/[lang]/page.js" switcher
// You now have access to the current locale
// e.g. /en-US/products -> `lang` is "en-US"
export default async function Page({ params }) {
  const { lang } = await params
  return ...
}
```

> **Bom saber:** `PageProps` e `LayoutProps` são helpers de TypeScript disponíveis globalmente que fornecem tipagem forte para os parâmetros de rota. Veja [PageProps](/docs/app/api-reference/file-conventions/page#page-props-helper) e [LayoutProps](/docs/app/api-reference/file-conventions/layout#layout-props-helper) para mais detalhes.

O root layout também pode ser aninhado na nova pasta (por exemplo, `app/[lang]/layout.js`).

## Localização \{#localization}

Alterar o conteúdo exibido com base no locale preferido do usuário, ou localização, não é algo específico do Next.js. Os padrões descritos abaixo funcionariam da mesma forma em qualquer app web.

Vamos supor que queremos oferecer conteúdo em inglês e em holandês no nosso app. Podemos manter dois "dicionários" diferentes, que são objetos que mapeiam uma chave para uma string localizada. Por exemplo:

```json filename="dictionaries/en.json"
{
  "products": {
    "cart": "Add to Cart"
  }
}
```

```json filename="dictionaries/nl.json"
{
  "products": {
    "cart": "Toevoegen aan Winkelwagen"
  }
}
```

Podemos então criar uma função `getDictionary` para carregar as traduções do locale solicitado:

```ts filename="app/[lang]/dictionaries.ts" switcher
import 'server-only'

const dictionaries = {
  en: () => import('./dictionaries/en.json').then((module) => module.default),
  nl: () => import('./dictionaries/nl.json').then((module) => module.default),
}

export type Locale = keyof typeof dictionaries

export const hasLocale = (locale: string): locale is Locale =>
  locale in dictionaries

export const getDictionary = async (locale: Locale) => dictionaries[locale]()
```

```js filename="app/[lang]/dictionaries.js" switcher
import 'server-only'

const dictionaries = {
  en: () => import('./dictionaries/en.json').then((module) => module.default),
  nl: () => import('./dictionaries/nl.json').then((module) => module.default),
}

export const hasLocale = (locale) => locale in dictionaries

export const getDictionary = async (locale) => dictionaries[locale]()
```

Com o idioma selecionado, podemos buscar o dicionário dentro de um layout ou página.

Como `lang` é tipado como `string`, usar `hasLocale` restringe o tipo aos locales aceitos. Chamar `notFound()` para um locale não aceito renderiza a UI de não encontrado.

```tsx filename="app/[lang]/page.tsx" switcher
import { notFound } from 'next/navigation'
import { getDictionary, hasLocale } from './dictionaries'

export default async function Page({ params }: PageProps<'/[lang]'>) {
  const { lang } = await params

  if (!hasLocale(lang)) notFound()

  const dict = await getDictionary(lang)
  return <button>{dict.products.cart}</button> // Add to Cart
}
```

```jsx filename="app/[lang]/page.js" switcher
import { notFound } from 'next/navigation'
import { getDictionary, hasLocale } from './dictionaries'

export default async function Page({ params }) {
  const { lang } = await params

  if (!hasLocale(lang)) notFound()

  const dict = await getDictionary(lang)
  return <button>{dict.products.cart}</button> // Add to Cart
}
```

Como todos os layouts e páginas no diretório `app/` usam [Server Components](/docs/app/getting-started/server-and-client-components) por padrão, não precisamos nos preocupar com o tamanho dos arquivos de tradução afetando o tamanho do bundle JavaScript do cliente. Esse código **roda apenas no servidor**, e somente o HTML resultante é enviado ao navegador.

## Compartilhando o locale no seu app \{#sharing-the-locale-across-your-app}

O locale costuma ser necessário além da página que o recebe, como em utilitários compartilhados de busca de dados ou em componentes profundamente aninhados. Em vez de repassar `lang` por props em cada camada (prop drilling), podemos lê-lo diretamente com [`next/root-params`](/docs/app/api-reference/functions/next-root-params).

`next/root-params` exporta um getter para cada segmento dinâmico acima do root layout. Como todas as rotas estão aninhadas em `app/[lang]`, `lang` é um root param, e qualquer Server Component ou utilitário do lado do servidor pode chamar o getter. Podemos mover a busca do locale para dentro de `getDictionary`, para que quem chama não precise mais passar `lang`:

```ts filename="app/[lang]/dictionaries.ts" highlight={1,2,15,16,17} switcher
import { lang } from 'next/root-params'
import { notFound } from 'next/navigation'

const dictionaries = {
  en: () => import('./dictionaries/en.json').then((module) => module.default),
  nl: () => import('./dictionaries/nl.json').then((module) => module.default),
}

export type Locale = keyof typeof dictionaries

export const hasLocale = (locale: string): locale is Locale =>
  locale in dictionaries

export const getDictionary = async () => {
  const locale = await lang()
  if (!hasLocale(locale)) notFound()
  return dictionaries[locale]()
}
```

```js filename="app/[lang]/dictionaries.js" highlight={1,2,12,13,14} switcher
import { lang } from 'next/root-params'
import { notFound } from 'next/navigation'

const dictionaries = {
  en: () => import('./dictionaries/en.json').then((module) => module.default),
  nl: () => import('./dictionaries/nl.json').then((module) => module.default),
}

export const hasLocale = (locale) => locale in dictionaries

export const getDictionary = async () => {
  const locale = await lang()
  if (!hasLocale(locale)) notFound()
  return dictionaries[locale]()
}
```

> **Bom saber:** arquivos que importam de `next/root-params` não precisam de `import 'server-only'`. O import já falha no build se for usado em um Client Component.

Páginas e componentes então chamam `getDictionary()` sem argumentos, já que o locale é resolvido internamente:

```tsx filename="app/[lang]/page.tsx" highlight={4} switcher
import { getDictionary } from './dictionaries'

export default async function Page() {
  const dict = await getDictionary()
  return <button>{dict.products.cart}</button> // Add to Cart
}
```

```jsx filename="app/[lang]/page.js" highlight={4} switcher
import { getDictionary } from './dictionaries'

export default async function Page() {
  const dict = await getDictionary()
  return <button>{dict.products.cart}</button> // Add to Cart
}
```

> **Bom saber:** os getters de root params rodam em Server Components e utilitários do lado do servidor, mas não em Client Components, Server Actions ou Route Handlers. Veja [`next/root-params`](/docs/app/api-reference/functions/next-root-params) para a API completa e seu comportamento com cache.

## Static Rendering \{#static-rendering}

Para gerar rotas estáticas para um conjunto de locales, podemos usar `generateStaticParams` em qualquer página ou layout. Isso pode ser feito de forma global, por exemplo, no root layout:

```tsx filename="app/[lang]/layout.tsx" switcher
export async function generateStaticParams() {
  return [{ lang: 'en-US' }, { lang: 'de' }]
}

export default async function RootLayout({
  children,
  params,
}: LayoutProps<'/[lang]'>) {
  return (
    <html lang={(await params).lang}>
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/[lang]/layout.js" switcher
export async function generateStaticParams() {
  return [{ lang: 'en-US' }, { lang: 'de' }]
}

export default async function RootLayout({ children, params }) {
  return (
    <html lang={(await params).lang}>
      <body>{children}</body>
    </html>
  )
}
```
