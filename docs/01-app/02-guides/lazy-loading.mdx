O [lazy loading](https://developer.mozilla.org/docs/Web/Performance/Lazy_loading) no Next.js ajuda a melhorar o desempenho do carregamento inicial de um app, diminuindo a quantidade de JavaScript necessária para renderizar uma rota.

<AppOnly>

Ele permite adiar o carregamento de **Client Components** e de bibliotecas importadas, incluindo-os no bundle do cliente somente quando forem necessários. Por exemplo, adie o carregamento de um modal até que o usuário clique para abri-lo.

Há duas formas de implementar lazy loading no Next.js:

1. Usando [importações dinâmicas](#nextdynamic) com `next/dynamic`
2. Usando [`React.lazy()`](https://react.dev/reference/react/lazy) com [Suspense](https://react.dev/reference/react/Suspense)

Por padrão, os Server Components são divididos automaticamente em partes ([code splitting](https://developer.mozilla.org/docs/Glossary/Code_splitting)), e você pode usar [streaming](/docs/app/guides/streaming) para enviar progressivamente partes da UI do servidor para o cliente. O lazy loading se aplica aos Client Components.

## `next/dynamic` \{#nextdynamic}

`next/dynamic` é uma composição de [`React.lazy()`](https://react.dev/reference/react/lazy) e [Suspense](https://react.dev/reference/react/Suspense). Ele se comporta da mesma forma nos diretórios `app` e `pages`, para permitir uma migração incremental.

## Exemplos \{#examples}

### Importando Client Components \{#importing-client-components}

```jsx filename="app/page.js"
'use client'

import { useState } from 'react'
import dynamic from 'next/dynamic'

// Client Components:
const ComponentA = dynamic(() => import('../components/A'))
const ComponentB = dynamic(() => import('../components/B'))
const ComponentC = dynamic(() => import('../components/C'), { ssr: false })

export default function ClientComponentExample() {
  const [showMore, setShowMore] = useState(false)

  return (
    <div>
      {/* Load immediately, but in a separate client bundle */}
      <ComponentA />

      {/* Load on demand, only when/if the condition is met */}
      {showMore && <ComponentB />}
      <button onClick={() => setShowMore(!showMore)}>Toggle</button>

      {/* Load only on the client side */}
      <ComponentC />
    </div>
  )
}
```

> **Nota:** quando um Server Component importa dinamicamente um Client Component, a divisão automática de código ([code splitting](https://developer.mozilla.org/docs/Glossary/Code_splitting)) ainda **não** tem suporte.

### Desativando o SSR \{#skipping-ssr}

Ao usar `React.lazy()` e Suspense, os Client Components passam por [prerendering](https://github.com/reactwg/server-components/discussions/4) (SSR) por padrão.

> **Nota:** a opção `ssr: false` só funciona com Client Components. Mova-a para dentro de Client Components para garantir que a divisão de código no cliente funcione corretamente.

Se você quiser desativar o prerendering de um Client Component, use a opção `ssr` definida como `false`:

```jsx
const ComponentC = dynamic(() => import('../components/C'), { ssr: false })
```

### Importando Server Components \{#importing-server-components}

Se você importar dinamicamente um Server Component, apenas os Client Components que são filhos dele serão carregados de forma lazy, e não o próprio Server Component.
Também ajuda a carregar antecipadamente recursos estáticos, como CSS, quando ele é usado em Server Components.

```jsx filename="app/page.js"
import dynamic from 'next/dynamic'

// Server Component:
const ServerComponent = dynamic(() => import('../components/ServerComponent'))

export default function ServerComponentExample() {
  return (
    <div>
      <ServerComponent />
    </div>
  )
}
```

> **Nota:** a opção `ssr: false` não é aceita em Server Components. Você verá um erro se tentar usá-la neles.
> `ssr: false` não é permitida com `next/dynamic` em Server Components. Mova-a para um Client Component.

### Carregando bibliotecas externas \{#loading-external-libraries}

Bibliotecas externas podem ser carregadas sob demanda usando a função [`import()`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Operators/import). Este exemplo usa a biblioteca externa `fuse.js` para busca aproximada. O módulo só é carregado no cliente depois que o usuário digita no campo de busca.

```jsx filename="app/page.js"
'use client'

import { useState } from 'react'

const names = ['Tim', 'Joe', 'Bel', 'Lee']

export default function Page() {
  const [results, setResults] = useState()

  return (
    <div>
      <input
        type="text"
        placeholder="Search"
        onChange={async (e) => {
          const { value } = e.currentTarget
          // Dynamically load fuse.js
          const Fuse = (await import('fuse.js')).default
          const fuse = new Fuse(names)

          setResults(fuse.search(value))
        }}
      />
      <pre>Results: {JSON.stringify(results, null, 2)}</pre>
    </div>
  )
}
```

### Adicionando um componente de carregamento personalizado \{#adding-a-custom-loading-component}

```jsx filename="app/page.js"
'use client'

import dynamic from 'next/dynamic'

const WithCustomLoading = dynamic(
  () => import('../components/WithCustomLoading'),
  {
    loading: () => <p>Loading...</p>,
  }
)

export default function Page() {
  return (
    <div>
      {/* The loading component will be rendered while  <WithCustomLoading/> is loading */}
      <WithCustomLoading />
    </div>
  )
}
```

### Importando exports nomeados \{#importing-named-exports}

Para importar dinamicamente um export nomeado, você pode retorná-lo a partir da Promise retornada pela função [`import()`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Operators/import):

```jsx filename="components/hello.js"
'use client'

export function Hello() {
  return <p>Hello!</p>
}
```

```jsx filename="app/page.js"
import dynamic from 'next/dynamic'

const ClientComponent = dynamic(() =>
  import('../components/hello').then((mod) => mod.Hello)
)
```

## Comentários mágicos \{#magic-comments}

O Next.js aceita comentários mágicos (magic comments) para controlar como o bundler trata as importações dinâmicas. Esses comentários funcionam com expressões dinâmicas `import()`, `require()`, `require.resolve()` e `new Worker()`.

> **Bom saber:** comentários mágicos não funcionam com instruções `import` estáticas (`import x from 'y'`). Eles funcionam apenas com expressões dinâmicas.

### `webpackIgnore` / `turbopackIgnore` \{#webpackignore--turbopackignore}

Use esses comentários para ignorar o bundling de uma importação dinâmica. A expressão de importação será mantida como está na saída, o que é útil para módulos que existem apenas em runtime:

```js
// Skip bundling - import happens at runtime
const runtime = await import(/* webpackIgnore: true */ 'runtime-module')

// Turbopack-specific variant
const plugin = await import(/* turbopackIgnore: true */ pluginPath)

// Also works with require
const mod = require(/* webpackIgnore: true */ 'runtime-module')
```

### `turbopackOptional` (apenas Turbopack) \{#turbopackoptional-turbopack-only}

Use este comentário para suprimir erros de build quando um módulo pode não existir. A importação ainda vai lançar um erro em runtime se o módulo estiver ausente:

```js
// No build error if './optional-feature' doesn't exist
// Runtime will throw MODULE_NOT_FOUND if executed
const feature = await import(/* turbopackOptional: true */ './optional-feature')

// Also works with require
const mod = require(/* turbopackOptional: true */ './optional-module')
```

Isso é útil para:

- Funcionalidades condicionais que podem não estar instaladas
- Sistemas de plugins em que os módulos são opcionais
- Migrações graduais em que alguns arquivos ainda podem não existir

> **Bom saber:** `webpackOptional` não é aceito. Use `turbopackOptional` ao usar o Turbopack.

## `next/dynamic` \{#nextdynamic}

`next/dynamic` é uma composição de [`React.lazy()`](https://react.dev/reference/react/lazy) e [Suspense](https://react.dev/reference/react/Suspense). Ele se comporta da mesma forma nos diretórios `app` e `pages`, para permitir uma migração incremental.

No exemplo abaixo, ao usar `next/dynamic`, o componente de cabeçalho não será incluído no bundle JavaScript inicial da página. A página vai renderizar primeiro o `fallback` do Suspense, seguido do componente `Header` quando o limite do `Suspense` for resolvido.

```jsx
import dynamic from 'next/dynamic'

const DynamicHeader = dynamic(() => import('../components/header'), {
  loading: () => <p>Loading...</p>,
})

export default function Home() {
  return <DynamicHeader />
}
```

> **Bom saber**: em `import('path/to/component')`, o caminho precisa estar escrito explicitamente. Ele não pode ser uma template string nem uma variável. Além disso, o `import()` precisa estar dentro da chamada de `dynamic()` para que o Next.js consiga associar os bundles do webpack / IDs de módulos à chamada específica de `dynamic()` e carregá-los antecipadamente antes da renderização. `dynamic()` não pode ser usado dentro da renderização do React, pois precisa estar marcado no nível superior do módulo para que o carregamento antecipado funcione, assim como acontece com `React.lazy`.

## Exemplos \{#examples}

### Com exports nomeados \{#with-named-exports}

Para importar dinamicamente um export nomeado, você pode retorná-lo a partir da [Promise](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Promise) retornada pela [`import()`](https://github.com/tc39/proposal-dynamic-import#example):

```jsx filename="components/hello.js"
export function Hello() {
  return <p>Hello!</p>
}

// pages/index.js
import dynamic from 'next/dynamic'

const DynamicComponent = dynamic(() =>
  import('../components/hello').then((mod) => mod.Hello)
)
```

### Sem SSR \{#with-no-ssr}

Para carregar dinamicamente um componente no lado do cliente, use a opção `ssr` para desativar a renderização no servidor. Isso é útil se uma dependência externa ou componente depender de APIs do navegador, como `window`.

```jsx
'use client'

import dynamic from 'next/dynamic'

const DynamicHeader = dynamic(() => import('../components/header'), {
  ssr: false,
})
```

### Com bibliotecas externas \{#with-external-libraries}

Este exemplo usa a biblioteca externa `fuse.js` para busca aproximada. O módulo só é carregado no navegador depois que o usuário digita no campo de busca.

```jsx
import { useState } from 'react'

const names = ['Tim', 'Joe', 'Bel', 'Lee']

export default function Page() {
  const [results, setResults] = useState()

  return (
    <div>
      <input
        type="text"
        placeholder="Search"
        onChange={async (e) => {
          const { value } = e.currentTarget
          // Dynamically load fuse.js
          const Fuse = (await import('fuse.js')).default
          const fuse = new Fuse(names)

          setResults(fuse.search(value))
        }}
      />
      <pre>Results: {JSON.stringify(results, null, 2)}</pre>
    </div>
  )
}
```
