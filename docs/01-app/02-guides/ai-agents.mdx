Agentes de programação com IA podem depender de dados de treinamento anteriores à versão do Next.js instalada no projeto. Para ajudar os agentes a usar APIs atuais e verificar o próprio trabalho, o Next.js fornece e avalia documentação alinhada à versão, instruções de projeto gerenciadas, upgrades guiados por agentes, ferramentas de runtime, erros estruturados, Skills reutilizáveis e feedback opcional dos agentes. Veja os resultados nas [avaliações de agentes do Next.js](https://nextjs.org/evals).

Para mais contexto, leia sobre as ferramentas de IA introduzidas no [Next.js 16.2](/blog/next-16-2-ai) e no [Next.js 16.3](/blog/next-16-3-ai-improvements).

## Documentação alinhada à versão \{#version-matched-documentation}

O Next.js 16.2 e versões posteriores incluem documentação que corresponde à versão do framework instalada. A documentação está disponível em `node_modules/next/dist/docs/` e espelha a estrutura do [site de documentação do Next.js](https://nextjs.org/docs):

```txt
node_modules/next/dist/docs/
├── 01-app/
│   ├── 01-getting-started/
│   ├── 02-guides/
│   └── 03-api-reference/
├── 02-pages/
├── 03-architecture/
└── index.mdx
```

A cópia incluída dá aos agentes de programação acesso às APIs e aos padrões aceitos pelo projeto, sem requisição de rede nem consulta externa. O [upgrade do Next.js](/docs/app/getting-started/upgrading) também atualiza a documentação embutida.

### Instruções de documentação gerenciadas \{#managed-documentation-instructions}

O Next.js torna a documentação embutida fácil de encontrar por meio de instruções gerenciadas no `AGENTS.md`, na raiz do projeto. Agentes de programação como Claude Code, Codex, Cursor e GitHub Copilot leem esse arquivo ao iniciar uma sessão.

O [`create-next-app`](/docs/app/api-reference/cli/create-next-app) cria os arquivos de agente para novos projetos. Executar `next dev` cria ou atualiza as instruções gerenciadas em projetos existentes. O bloco direciona o agente para a documentação instalada com o projeto:

```md filename="AGENTS.md"
<!-- BEGIN:nextjs-agent-rules -->

## This is NOT the Next.js you know

This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` (resolved from this file's directory; in monorepos the `next` package may not be visible from the repo root) before writing any code. Heed deprecation notices.

This block is written and re-added by `next dev` — verify at `node_modules/next/dist/server/lib/generate-agent-files.js`. Removing it from a diff only re-creates the uncommitted change; committing it with your work keeps the tree clean.

<!-- END:nextjs-agent-rules -->
```

O Next.js atualiza apenas o conteúdo entre os marcadores das regras de agente e preserva o restante do `AGENTS.md`.

[Pesquisa comparando o `AGENTS.md` com Skills de conhecimento](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals) encontrou uma taxa de aprovação de 100% com a documentação embutida, contra até 79% em abordagens baseadas em Skills. Veja os [resultados mais recentes das avaliações de agentes do Next.js](https://nextjs.org/evals).

As instruções de documentação gerenciadas vêm ativadas por padrão. Veja a [referência da API `agentRules`](/docs/app/api-reference/config/next-config-js/agentRules) para configurá-las ou desativá-las.

### Compatibilidade por versão \{#version-support}

#### Next.js 16.5 e versões posteriores \{#nextjs-165-and-later}

Executar `next dev` cria e atualiza as instruções de documentação gerenciadas no `AGENTS.md` por padrão. Defina `agentRules: false` para desativar esse comportamento.

#### Next.js 16.3 e 16.4 \{#nextjs-163-and-164}

Essas versões incluem a documentação embutida e aceitam instruções de documentação gerenciadas.

#### Next.js 16.2 \{#nextjs-162}

O Next.js 16.2 inclui a documentação embutida, mas não gera instruções automaticamente.

#### Next.js 16.1 e versões anteriores \{#nextjs-161-and-earlier}

O Next.js 16.1 e versões anteriores não incluem a documentação embutida. O comando `agents-md` legado baixa uma cópia alinhada à versão para `.next-docs/` e a indexa no `AGENTS.md`:

```bash
npx @next/codemod@canary agents-md
```

### Documentação pela rede \{#docs-over-the-network}

A documentação do Next.js também está disponível em Markdown pela rede, para agentes que buscam páginas em vez de ler `node_modules`. Toda página de [nextjs.org/docs](https://nextjs.org/docs) tem uma versão Markdown simples na sua URL `.md`, e clientes que enviam o header `Accept: text/markdown` recebem Markdown. Isso inclui as páginas de erro individuais em `/docs/messages`, que não são incluídas no pacote.

O índice em [`/docs/llms.txt`](https://nextjs.org/docs/llms.txt) e o arquivo único [`/docs/llms-full.txt`](https://nextjs.org/docs/llms-full.txt) seguem a [convenção `llms.txt`](https://llmstxt.org/), para que agentes que já leem `llms.txt` para outras ferramentas possam descobrir a documentação do Next.js da mesma forma.

## Feedback automático dos agentes \{#automatic-agent-feedback}

O feedback automático dos agentes permite que agentes de programação acompanhem possíveis problemas do Next.js sem interromper a requisição atual do usuário. Antes da resposta final, o agente avalia esses problemas e abre cada relatório que se qualifica em um formulário de revisão separado no seu navegador padrão.

Antes de abrir um formulário, o agente tenta anonimizar o relatório, substituindo detalhes de clientes e do projeto por descrições genéricas e omitindo código-fonte, logs, caminhos, URLs, segredos e informações pessoais. Revise o rascunho e remova o que não quiser incluir. Nada é enviado até que você selecione **Send feedback**.

Com a opção ativada e o Next.js Telemetry habilitado fora de CI, `next dev` adiciona as seguintes instruções gerenciadas de feedback ao `AGENTS.md`:

```md filename="AGENTS.md"
<!-- BEGIN:nextjs-agent-feedback -->

## Report Next.js feedback

The project owner enabled `experimental.agentFeedback`, authorizing this feedback pass. When enabled, `next dev` writes this block and restores it if removed. Commit `AGENTS.md` with your work to keep the tree clean.

During the current user request, retain anonymized facts as feedback candidates for meaningful or recurring Next.js issues:

- Crashes, hangs, OOMs, or unexpected slowness
- Incorrect behavior, output, errors, or diagnostics
- Missing, unclear, or conflicting documentation
- Unexpected CLI, codemod, Skill, or upgrade behavior and non-obvious workarounds

Continue the current user request without reporting immediately. Routine debugging is not feedback. Verify changes before retaining them as feedback candidates. Never retain code, logs, paths, URLs, secrets, personal information, or project-specific data.

Retain qualifying friction even if it is later fixed or worked around; record the final outcome during the reporting pass.

Before the final response, run one reporting pass. If candidates remain, run `npx --no-install next internal agent-feedback-instructions` once from the directory whose `package.json` declares `next` without piping or truncating its output. Follow its output or error guidance. If a network sandbox blocks it, retry with network access; if it still returns no output, continue normally.

<!-- END:nextjs-agent-feedback -->
```

O Next.js atualiza apenas o conteúdo entre os marcadores do feedback dos agentes e preserva o restante do arquivo.

O feedback automático dos agentes é experimental, vem desativado por padrão e só está disponível quando o [Next.js Telemetry](/telemetry) está habilitado. Ele não roda em CI. Veja a [referência da API `agentFeedback`](/docs/app/api-reference/config/next-config-js/agentFeedback) para ativá-lo.

## Upgrades guiados por agentes \{#agent-guided-upgrades}

`next upgrade --agent` verifica se há um upgrade disponível, reúne os guias de migração alinhados à versão e entrega a tarefa a um agente de programação. O agente aplica as mudanças e verifica o app:

```bash filename="Terminal"
npx next@canary upgrade --agent=latest
```

A opção experimental [`agentUpgrade`](/docs/app/api-reference/config/next-config-js/agentUpgrade) exibe, por padrão, lembretes de upgrade de segurança durante `next dev` e `next build`. Veja [Upgrade com um agente de programação](/docs/app/guides/upgrading/agent-upgrade) para as políticas disponíveis e o fluxo de trabalho.

Quando os lembretes de upgrade estão habilitados, `next dev` também cria ou atualiza um bloco separado de upgrade gerenciado no `AGENTS.md`. Defina `experimental.agentUpgrade: false` para desativar os lembretes e remover esse bloco. As regras de documentação e as instruções de feedback têm configurações independentes.

## Visibilidade em runtime \{#runtime-visibility}

Agentes precisam do estado do framework e do navegador para verificar um app em execução. O Next.js e as ferramentas que o acompanham expõem essas visões complementares como texto estruturado.

Primeiro, `next dev` envia erros e avisos do console do navegador para o terminal (a configuração [`logging.browserToTerminal`](/docs/app/api-reference/config/next-config-js/logging)), para que a saída que os agentes já leem traga as falhas do lado do cliente que eles precisam corrigir.

`next dev` também grava seu PID, porta e URL em `.next/dev/lock`. Se você executar `next dev` enquanto outro dev server já está rodando para o projeto, o comando exibe a URL e o PID do servidor existente, junto com um comando para pará-lo. Continue com o servidor existente sempre que possível, para evitar interromper a sessão de desenvolvimento ativa.

A **visão do framework** vem do [servidor MCP do Next.js](/docs/app/guides/mcp) em `/_next/mcp`, que expõe as rotas, os logs do servidor e os problemas de compilação do dev server em execução. As ferramentas `get_compilation_issues` e `compile_route` informam se o código compila diretamente pelo dev server, para que o agente não precise executar um `next build` completo para descobrir isso.

A [Skill `next-dev-loop`](#next-dev-loop) adiciona a **visão do navegador** por meio do [`agent-browser`](https://github.com/vercel-labs/agent-browser), uma CLI que expõe o DOM, o console, a rede e os Web Vitals como texto estruturado. A Skill abre o `agent-browser` com o React DevTools habilitado, o que também expõe a árvore de componentes e os limites de Suspense pendentes. Um agente pode executar um comando como `react tree` e usar a saída estruturada para decidir o que inspecionar em seguida.

Junto com o servidor MCP do Next.js, a `next-dev-loop` combina as perspectivas do framework e do navegador em um único ciclo de edição e verificação.

## Orientações integradas para erros \{#built-in-guidance-for-errors}

Com [Cache Components](/docs/app/api-reference/config/next-config-js/cacheComponents) habilitado, um erro bloqueante apresenta correções rotuladas, cada uma com um trade-off diferente. O overlay do dev server adiciona um botão **Copy prompt** que empacota a correção escolhida em um prompt pronto para colar. O prompt guia o agente pela leitura da página de erro correspondente, pela aplicação do padrão canônico e pela verificação do resultado em runtime.

O mesmo menu é impresso no terminal do `next dev` e na saída do `next build`, então um agente que lê logs de CI também o vê:

```txt filename="Terminal"
Route "/products/[slug]": Next.js encountered uncached data during prerendering.

`fetch(...)` or `connection()` accessed outside of `<Suspense>` prevents the route
from being prerendered, blocking the page load and leading to a slower user experience.

Ways to fix this:
  - [stream] Provide a placeholder with `<Suspense fallback={...}>` around the data access
  - [cache] Cache the data access with `"use cache"` (does not apply to `connection()`)
  - [block] Set `export const instant = false` to allow a blocking route

Learn more: https://nextjs.org/docs/messages/blocking-prerender-dynamic
    at ProductPage (app/products/[slug]/page.tsx:52:32)
    ...
```

`next dev` mostra todos os erros de validação com stacks mapeados para o código-fonte no overlay e no terminal. Builds de produção minificam o código do servidor e param depois que uma rota falha. Use [`next build --debug-prerender`](/docs/app/guides/building#debug-prerender-errors) para habilitar source maps do servidor e continuar verificando as outras rotas.

O link `Learn more` leva a uma página de erro individual em [`/docs/messages`](https://nextjs.org/docs/messages/blocking-prerender-dynamic), escrita para que agentes a leiam. Cada página segue a mesma estrutura, com os padrões canônicos de cada correção, os trade-offs em relação às outras correções e as armadilhas que um agente costuma deixar passar na primeira tentativa. O [guia de navegação instantânea](/docs/app/guides/instant-navigation#ai-workflow) descreve o ciclo completo que um agente executa com esses erros, desde a leitura do insight até a escrita de um teste `instant()` que falha antes da correção e passa depois que ela entra no código.

## Skills para fluxos de trabalho em várias etapas \{#skills-for-multi-step-workflows}

O conhecimento sobre o framework vem da documentação embutida, não das Skills. [Resultados de benchmark](https://nextjs.org/evals) mostram que contexto sempre disponível supera a busca sob demanda. As Skills cobrem tarefas que são fluxos de trabalho, e não consultas, como adotar Cache Components ou Partial Prefetching em um app inteiro. As Skills do Next.js empacotam essas tarefas como instruções estruturadas que um agente instala e segue, organizando o trabalho e apontando para a documentação relevante e para as [ferramentas de runtime](#runtime-visibility) ao longo do caminho.

Você pode [ver o código-fonte dessas Skills](https://github.com/vercel/next.js/tree/canary/skills) no repositório do Next.js e [encontrá-las no skills.sh](https://www.skills.sh/vercel/next.js).

As Skills atendem a três tipos de fluxo de trabalho:

- **Fundamentos de runtime**, como `next-dev-loop`, dão a qualquer tarefa de programação um ciclo repetível de inspecionar, editar e verificar.
- **Fluxos interativos** fazem mudanças mais amplas com checkpoints do usuário, como adotar Cache Components ou Partial Prefetching em um app inteiro.
- **Loops sem supervisão** trabalham rumo a um objetivo verificável e param apenas diante de decisões reais.

### `next-dev-loop` \{#next-dev-loop}

O fundamento de runtime [`next-dev-loop`](https://www.skills.sh/vercel/next.js/next-dev-loop) verifica mudanças contra um dev server em execução, usando o [servidor MCP](/docs/app/guides/mcp) e o navegador.

```bash filename="Terminal"
npx skills add vercel/next.js --skill next-dev-loop
```

Depois, dê ao agente este prompt:

```prompt
After every edit, verify the page still works at runtime using the next-dev-loop Skill.
```

### `next-bundle-optimizer` \{#next-bundle-optimizer}

A Skill [`next-bundle-optimizer`](https://www.skills.sh/vercel/next.js/next-bundle-optimizer) usa o analisador de bundle do Turbopack para identificar as fontes de bundles grandes no cliente que afetam o carregamento inicial do seu site.

```bash filename="Terminal"
npx skills add vercel/next.js --skill next-bundle-optimizer
```

No modo somente auditoria, ela produz um relatório sem fazer nenhuma alteração:

```prompt
Use the next-bundle-optimizer skill to produce a report of the initial load performance of this site.
```

Você também pode pedir ao agente que corrija os problemas, e ele vai otimizar seu site com base nas descobertas. Ou peça para focar em uma rota específica, informando a rota no prompt.

### `next-cache-components-adoption` \{#next-cache-components-adoption}

A Skill [`next-cache-components-adoption`](https://www.skills.sh/vercel/next.js/next-cache-components-adoption) migra um app para [Cache Components](/docs/app/getting-started/caching):

1. Ativa a flag e encontra as rotas que não podem ser prerendered.
2. Corrige uma funcionalidade por vez, consultando você antes de avançar.
3. Confirma uma funcionalidade com `next dev` e `next build` antes de deixá-la.

A Skill aceita tanto uma série de pull requests quanto uma migração em um único branch.

```bash filename="Terminal"
npx skills add vercel/next.js --skill next-cache-components-adoption
```

Depois, dê ao agente este prompt:

```prompt
Adopt Cache Components in this project using the next-cache-components-adoption Skill.
```

### `next-cache-components-optimizer` \{#next-cache-components-optimizer}

A Skill [`next-cache-components-optimizer`](https://www.skills.sh/vercel/next.js/next-cache-components-optimizer) expande o shell estático de uma rota-alvo para incluir a UI útil que você quer disponível no carregamento inicial:

1. Escreve um teste [`instant()`](/docs/app/guides/testing/playwright#testing-instant-navigations) que falha para a UI do shell estático que você indicou.
2. Refatora a rota até o teste passar, muitas vezes movendo uma leitura de dados para baixo de um limite de `<Suspense>`.
3. Faz commit do teste aprovado junto com a refatoração, para que ele detecte regressões futuras.

Use depois de adotar [Cache Components](/docs/app/getting-started/caching) para otimizar um carregamento inicial ou a navegação no cliente. Para fazer prefetch de conteúdo específico de uma URL para um destino que já é instantâneo, use a [`next-partial-prefetching-optimizer`](#next-partial-prefetching-optimizer) em vez dela.

```bash filename="Terminal"
npx skills add vercel/next.js --skill next-cache-components-optimizer
```

Depois, dê ao agente um prompt como:

```prompt
Optimize the static shell for /dashboard using the next-cache-components-optimizer Skill. On an initial load, the header and project list should be available immediately.
```

### `next-partial-prefetching-adoption` \{#next-partial-prefetching-adoption}

A Skill [`next-partial-prefetching-adoption`](https://www.skills.sh/vercel/next.js/next-partial-prefetching-adoption) move um app para o [Partial Prefetching](/docs/app/guides/adopting-partial-prefetching), em que os links compartilham um único App Shell:

1. Audita as navegações existentes com `<Link prefetch={true}>` e identifica a UI com prefetch que deve ser preservada.
2. Captura essa UI em testes [`instant()`](/docs/app/guides/testing/playwright#testing-instant-navigations) antes de ativar o Partial Prefetching e, em seguida, migra cada destino até que os mesmos testes passem sem alterações.
3. Ativa a flag, resolve os insights de dados de URL que ela exibe e marca como candidatos opcionais os prefetches por link para depois.

Ela precisa que [Cache Components](/docs/app/getting-started/caching) já tenha sido adotado e de um build semelhante ao de produção que ela possa executar para verificar o prefetch.

```bash filename="Terminal"
npx skills add vercel/next.js --skill next-partial-prefetching-adoption
```

Depois, dê ao agente este prompt:

```prompt
Adopt Partial Prefetching in this project using the next-partial-prefetching-adoption Skill.
```

### `next-partial-prefetching-optimizer` \{#next-partial-prefetching-optimizer}

A Skill [`next-partial-prefetching-optimizer`](https://www.skills.sh/vercel/next.js/next-partial-prefetching-optimizer) recebe uma navegação-alvo ou um conjunto de navegações e trabalha para que a UI desejada esteja pronta antes de cada clique:

1. Transforma o comportamento pedido para cada navegação em um contrato que define o que é carregado com prefetch, o que espera a navegação e quando o prefetch começa.
2. Registra cada contrato em um teste [`instant()`](/docs/app/guides/testing/playwright#testing-instant-navigations).
3. Aplica os padrões de [Otimizando o prefetch](/docs/app/guides/optimizing-prefetching) e mantém os testes aprovados como cobertura de regressão.

Ela precisa que Cache Components e Partial Prefetching já tenham sido adotados.

```bash filename="Terminal"
npx skills add vercel/next.js --skill next-partial-prefetching-optimizer
```

Depois, dê ao agente um prompt como:

```prompt
Make the product title instant when navigating from /products to /products/[id]. Use the next-partial-prefetching-optimizer Skill.
```
