O Next.js usa **roteamento baseado no sistema de arquivos**, o que significa que você pode usar pastas e arquivos para definir rotas. Esta página vai mostrar como criar layouts e páginas e como navegar entre eles.

## Criando uma página \{#creating-a-page}

Uma **página** é uma interface (UI) renderizada em uma rota específica. Para criar uma página, adicione um [arquivo `page`](/docs/app/api-reference/file-conventions/page) dentro do diretório `app` e exporte por padrão um componente React. Por exemplo, para criar uma página inicial (`/`):

<Image
  alt="Arquivo especial page.js"
  srcLight="/docs/light/page-special-file.png"
  srcDark="/docs/dark/page-special-file.png"
  width="1600"
  height="282"
/>

```tsx filename="app/page.tsx" switcher
export default function Page() {
  return <h1>Hello Next.js!</h1>
}
```

```jsx filename="app/page.js" switcher
export default function Page() {
  return <h1>Hello Next.js!</h1>
}
```

## Criando um layout \{#creating-a-layout}

Um layout é uma interface **compartilhada** entre várias páginas. Na navegação, os layouts preservam o estado, continuam interativos e não renderizam de novo.

Você pode definir um layout exportando por padrão um componente React de um [arquivo `layout`](/docs/app/api-reference/file-conventions/layout). O componente deve receber uma prop `children`, que pode ser uma página ou outro [layout](#nesting-layouts).

Por exemplo, para criar um layout que recebe sua página inicial como filho, adicione um arquivo `layout` dentro do diretório `app`:

<Image
  alt="Arquivo especial layout.js"
  srcLight="/docs/light/layout-special-file.png"
  srcDark="/docs/dark/layout-special-file.png"
  width="1600"
  height="363"
/>

```tsx filename="app/layout.tsx" switcher
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>
        {/* Layout UI */}
        {/* Place children where you want to render a page or nested layout */}
        <main>{children}</main>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function DashboardLayout({ children }) {
  return (
    <html lang="en">
      <body>
        {/* Layout UI */}
        {/* Place children where you want to render a page or nested layout */}
        <main>{children}</main>
      </body>
    </html>
  )
}
```

O layout acima é chamado de [layout raiz](/docs/app/api-reference/file-conventions/layout#root-layout) porque está definido na raiz do diretório `app`. O layout raiz é **obrigatório** e deve conter as tags `html` e `body`.

## Criando uma rota aninhada \{#creating-a-nested-route}

Uma rota aninhada é uma rota composta por vários segmentos de URL. Por exemplo, a rota `/blog/[slug]` é composta por três segmentos:

- `/` (Segmento raiz)
- `blog` (Segmento)
- `[slug]` (Segmento folha)

No Next.js:

- **Pastas** são usadas para definir os segmentos de rota que correspondem aos segmentos de URL.
- **Arquivos** (como `page` e `layout`) são usados para criar a interface exibida para um segmento.

Para criar rotas aninhadas, você pode colocar pastas umas dentro das outras. Por exemplo, para adicionar uma rota para `/blog`, crie uma pasta chamada `blog` no diretório `app`. Depois, para tornar `/blog` acessível publicamente, adicione um arquivo `page.tsx`:

<Image
  alt="Hierarquia de arquivos mostrando a pasta blog e um arquivo page.js"
  srcLight="/docs/light/blog-nested-route.png"
  srcDark="/docs/dark/blog-nested-route.png"
  width="1600"
  height="525"
/>

```tsx filename="app/blog/page.tsx" switcher
// Dummy imports
import { getPosts } from '@/lib/posts'
import { Post } from '@/ui/post'

export default async function Page() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <Post key={post.id} post={post} />
      ))}
    </ul>
  )
}
```

```jsx filename="app/blog/page.js" switcher
// Dummy imports
import { getPosts } from '@/lib/posts'
import { Post } from '@/ui/post'

export default async function Page() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <Post key={post.id} post={post} />
      ))}
    </ul>
  )
}
```

Você pode continuar aninhando pastas para criar rotas aninhadas. Por exemplo, para criar uma rota para um post específico do blog, crie uma nova pasta `[slug]` dentro de `blog` e adicione um arquivo `page`:

<Image
  alt="Hierarquia de arquivos mostrando a pasta blog com uma pasta slug aninhada e um arquivo page.js"
  srcLight="/docs/light/blog-post-nested-route.png"
  srcDark="/docs/dark/blog-post-nested-route.png"
  width="1600"

/>

```tsx filename="app/blog/[slug]/page.tsx" switcher

export default function Page() {
  return <h1>Hello, Blog Post Page!</h1>
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
export function generateStaticParams() {}

export default function Page() {
  return <h1>Hello, Blog Post Page!</h1>
}
```

Colocar o nome de uma pasta entre colchetes (por exemplo, `[slug]`) cria um [segmento de rota dinâmico](/docs/app/api-reference/file-conventions/dynamic-routes), usado para gerar várias páginas a partir de dados. Por exemplo, posts de blog, páginas de produto etc.

## Aninhando layouts \{#nesting-layouts}

Por padrão, os layouts na hierarquia de pastas também são aninhados, o que significa que eles envolvem os layouts filhos pela prop `children`. Você pode aninhar layouts adicionando `layout` dentro de segmentos de rota (pastas) específicos.

Por exemplo, para criar um layout para a rota `/blog`, adicione um novo arquivo `layout` dentro da pasta `blog`.

<Image
  alt="Hierarquia de arquivos mostrando o layout raiz envolvendo o layout do blog"
  srcLight="/docs/light/nested-layouts.png"
  srcDark="/docs/dark/nested-layouts.png"
  width="1600"
  height="768"
/>

```tsx filename="app/blog/layout.tsx" switcher
export default function BlogLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return <section>{children}</section>
}
```

```jsx filename="app/blog/layout.js" switcher
export default function BlogLayout({ children }) {
  return <section>{children}</section>
}
```

Se você combinar os dois layouts acima, o layout raiz (`app/layout.js`) vai envolver o layout do blog (`app/blog/layout.js`), que vai envolver o blog (`app/blog/page.js`) e a página de post do blog (`app/blog/[slug]/page.js`).

## Criando um segmento dinâmico \{#creating-a-dynamic-segment}

[Segmentos dinâmicos](/docs/app/api-reference/file-conventions/dynamic-routes) permitem criar rotas geradas a partir de dados. Por exemplo, em vez de criar manualmente uma rota para cada post do blog, você pode criar um segmento dinâmico que gera as rotas com base nos dados dos posts.

Para criar um segmento dinâmico, coloque o nome do segmento (pasta) entre colchetes: `[segmentName]`. Por exemplo, na rota `app/blog/[slug]/page.tsx`, o `[slug]` é o segmento dinâmico.

```tsx filename="app/blog/[slug]/page.tsx" switcher
export default async function BlogPostPage({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  )
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
export default async function BlogPostPage({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  )
}
```

Saiba mais sobre [Segmentos dinâmicos](/docs/app/api-reference/file-conventions/dynamic-routes) e as props [`params`](/docs/app/api-reference/file-conventions/page#params-optional).

[Layouts dentro de segmentos dinâmicos](/docs/app/api-reference/file-conventions/layout#params-optional) também podem acessar as props `params`.

## Renderizando com parâmetros de busca \{#rendering-with-search-params}

Em uma **página** de Server Component, você pode acessar os parâmetros de busca usando a prop [`searchParams`](/docs/app/api-reference/file-conventions/page#searchparams-optional):

```tsx filename="app/page.tsx" switcher
export default async function Page({
  searchParams,
}: {
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}) {
  const filters = (await searchParams).filters
}
```

```jsx filename="app/page.jsx" switcher
export default async function Page({ searchParams }) {
  const filters = (await searchParams).filters
}
```

Usar `searchParams` faz sua página entrar em [**Dynamic Rendering**](/docs/app/glossary#dynamic-rendering), porque ela precisa de uma requisição recebida para ler os parâmetros de busca.

Client Components podem ler os parâmetros de busca usando o hook [`useSearchParams`](/docs/app/api-reference/functions/use-search-params).

Saiba mais sobre `useSearchParams` em rotas com [prerendering](/docs/app/api-reference/functions/use-search-params#prerendering) e [Dynamic Rendering](/docs/app/api-reference/functions/use-search-params#dynamic-rendering).

### O que usar e quando \{#what-to-use-and-when}

- Use a prop `searchParams` quando precisar dos parâmetros de busca para **carregar dados da página** (por exemplo, paginação ou filtragem vinda de um banco de dados).
- Use `useSearchParams` quando os parâmetros de busca forem usados **apenas no cliente** (por exemplo, filtrar uma lista já carregada por props).
- Como uma pequena otimização, você pode usar `new URLSearchParams(window.location.search)` em **callbacks ou manipuladores de eventos** para ler os parâmetros de busca sem disparar novas renderizações.

## Criando links entre páginas \{#linking-between-pages}

Você pode usar o [componente `<Link>`](/docs/app/api-reference/components/link) para navegar entre rotas. `<Link>` é um componente embutido do Next.js que estende a tag HTML `<a>` para oferecer [prefetching](/docs/app/getting-started/linking-and-navigating#prefetching) e [navegação no lado do cliente](/docs/app/getting-started/linking-and-navigating#client-side-transitions).

Por exemplo, para gerar uma lista de posts do blog, importe `<Link>` de `next/link` e passe uma prop `href` para o componente:

```tsx filename="app/ui/post.tsx" highlight={1,2,11} switcher
import Link from 'next/link'
import { getPosts } from '@/lib/posts'

export default async function Posts() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.slug}>
          <Link href={`/blog/${post.slug}`}>{post.title}</Link>
        </li>
      ))}
    </ul>
  )
}
```

```jsx filename="app/ui/post.js" highlight={1,2,11} switcher
import Link from 'next/link'
import { getPosts } from '@/lib/posts'

export default async function Posts() {
  const posts = await getPosts()

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.slug}>
          <Link href={`/blog/${post.slug}`}>{post.title}</Link>
        </li>
      ))}
    </ul>
  )
}
```

> **Bom saber**: `<Link>` é a forma principal de navegar entre rotas no Next.js. Você também pode usar o [hook `useRouter`](/docs/app/api-reference/functions/use-router) para navegações mais avançadas.

## Helpers de props de rota \{#route-props-helpers}

O Next.js expõe tipos utilitários que inferem `params` e slots nomeados a partir da estrutura das suas rotas:

- [**PageProps**](/docs/app/api-reference/file-conventions/page#page-props-helper): props para componentes `page`, incluindo `params` e `searchParams`.
- [**LayoutProps**](/docs/app/api-reference/file-conventions/layout#layout-props-helper): props para componentes `layout`, incluindo `children` e quaisquer slots nomeados (por exemplo, pastas como `@analytics`).

Estes são helpers globais, gerados ao executar `next dev`, `next build` ou [`next typegen`](/docs/app/api-reference/cli/next#next-typegen-options).

```tsx filename="app/blog/[slug]/page.tsx"
export default async function Page(props: PageProps<'/blog/[slug]'>) {
  const { slug } = await props.params
  return <h1>Blog post: {slug}</h1>
}
```

```tsx filename="app/dashboard/layout.tsx"
export default function Layout(props: LayoutProps<'/dashboard'>) {
  return (
    <section>
      {props.children}
      {/* If you have app/dashboard/@analytics, it appears as a typed slot: */}
      {/* {props.analytics} */}
    </section>
  )
}
```

> **Bom saber**
>
> - Rotas estáticas resolvem `params` para `{}`.
> - `PageProps` e `LayoutProps` são helpers globais, sem necessidade de importação.
> - Os tipos são gerados durante `next dev`, `next build` ou `next typegen`.
