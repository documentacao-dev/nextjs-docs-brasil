## Route Handlers \{#route-handlers}

Route Handlers permitem criar manipuladores de requisição personalizados para uma determinada rota, usando as APIs Web [Request](https://developer.mozilla.org/docs/Web/API/Request) e [Response](https://developer.mozilla.org/docs/Web/API/Response).

> **Bom saber**: Route Handlers estão disponíveis apenas dentro do diretório `app`. Eles são o equivalente às [API Routes](/docs/pages/building-your-application/routing/api-routes) do diretório `pages`, ou seja, você **não** precisa usar API Routes e Route Handlers juntos.

### Convenção \{#convention}

Route Handlers são definidos em um [arquivo `route.js|ts`](/docs/app/api-reference/file-conventions/route) dentro do diretório `app`:

```ts filename="app/api/route.ts" switcher
export async function GET(request: Request) {}
```

```js filename="app/api/route.js" switcher
export async function GET(request) {}
```

Route Handlers podem ser aninhados em qualquer lugar dentro do diretório `app`, da mesma forma que `page.js` e `layout.js`. Mas **não pode** haver um arquivo `route.js` no mesmo segmento de rota em que está o `page.js`.

### Métodos HTTP aceitos \{#supported-http-methods}

Os [métodos HTTP](https://developer.mozilla.org/docs/Web/HTTP/Methods) a seguir são aceitos: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD` e `OPTIONS`. Se um método não aceito for chamado, o Next.js retorna uma resposta `405 Method Not Allowed`.

### APIs estendidas `NextRequest` e `NextResponse` \{#extended-nextrequest-and-nextresponse-apis}

Além de dar suporte às APIs nativas [Request](https://developer.mozilla.org/docs/Web/API/Request) e [Response](https://developer.mozilla.org/docs/Web/API/Response), o Next.js as estende com [`NextRequest`](/docs/app/api-reference/functions/next-request) e [`NextResponse`](/docs/app/api-reference/functions/next-response), com funções auxiliares práticas para casos de uso avançados.

### Cache \{#caching}

Route Handlers não têm cache por padrão. Você pode, no entanto, optar por colocar em cache os métodos `GET`. Os outros métodos HTTP aceitos **não** têm cache. Para colocar em cache um método `GET`, use uma [opção de configuração de rota](/docs/app/guides/caching-without-cache-components#dynamic), como `export const dynamic = 'force-static'`, no arquivo do Route Handler.

```ts filename="app/items/route.ts" switcher
export const dynamic = 'force-static'

export async function GET() {
  const res = await fetch('https://data.mongodb-api.com/...', {
    headers: {
      'Content-Type': 'application/json',
      'API-Key': process.env.DATA_API_KEY,
    },
  })
  const data = await res.json()

  return Response.json({ data })
}
```

```js filename="app/items/route.js" switcher
export const dynamic = 'force-static'

export async function GET() {
  const res = await fetch('https://data.mongodb-api.com/...', {
    headers: {
      'Content-Type': 'application/json',
      'API-Key': process.env.DATA_API_KEY,
    },
  })
  const data = await res.json()

  return Response.json({ data })
}
```

> **Bom saber**: os outros métodos HTTP aceitos **não** têm cache, mesmo no mesmo arquivo de um método `GET` com cache.

#### Com Cache Components \{#with-cache-components}

Quando [Cache Components](/docs/app/getting-started/caching) estão habilitados, os métodos `GET` dos Route Handlers seguem o mesmo modelo das rotas de UI normais do app. Por padrão, eles rodam em tempo de requisição, podem ser prerenderizados quando não acessam dados sem cache nem de runtime, e você pode usar `use cache` para incluir dados sem cache na resposta estática.

**Exemplo estático** - não acessa dados sem cache nem de runtime, então é prerenderizado no build:

```tsx filename="app/api/project-info/route.ts"
export async function GET() {
  return Response.json({
    projectName: 'Next.js',
  })
}
```

**Exemplo dinâmico** - acessa operações não determinísticas. Durante o build, o prerendering para quando `Math.random()` é chamado, e o rendering passa a acontecer na requisição:

```tsx filename="app/api/random-number/route.ts"
export async function GET() {
  return Response.json({
    randomNumber: Math.random(),
  })
}
```

**Exemplo com dados de runtime** - acessa dados específicos da requisição. O prerendering termina quando APIs de runtime como `headers()` são chamadas:

```tsx filename="app/api/user-agent/route.ts"
import { headers } from 'next/headers'

export async function GET() {
  const headersList = await headers()
  const userAgent = headersList.get('user-agent')

  return Response.json({ userAgent })
}
```

> **Bom saber**: o prerendering para se o handler `GET` acessar requisições de rede, consultas a banco de dados, operações assíncronas de sistema de arquivos, propriedades do objeto de requisição (como `req.url`, `request.headers`, `request.cookies`, `request.body`), APIs de runtime como [`cookies()`](/docs/app/api-reference/functions/cookies), [`headers()`](/docs/app/api-reference/functions/headers), [`connection()`](/docs/app/api-reference/functions/connection), ou operações não determinísticas.

**Exemplo com cache** - acessa dados sem cache (uma consulta a banco de dados), mas o coloca em cache com `use cache`, o que permite incluí-los na resposta com prerendering:

```tsx filename="app/api/products/route.ts"
import { cacheLife } from 'next/cache'

export async function GET() {
  const products = await getProducts()
  return Response.json(products)
}

async function getProducts() {
  'use cache'
  cacheLife('hours')

  return await db.query('SELECT * FROM products')
}
```

> **Bom saber**: `use cache` não pode ser usado diretamente no corpo de um Route Handler. Extraia-o para uma função auxiliar. Respostas em cache são revalidadas conforme `cacheLife` quando chega uma nova requisição.

### Route Handlers especiais \{#special-route-handlers}

Route Handlers especiais, como [`sitemap.ts`](/docs/app/api-reference/file-conventions/metadata/sitemap), [`opengraph-image.tsx`](/docs/app/api-reference/file-conventions/metadata/opengraph-image) e [`icon.tsx`](/docs/app/api-reference/file-conventions/metadata/app-icons), e outros [arquivos de metadados](/docs/app/api-reference/file-conventions/metadata), permanecem estáticos por padrão, a menos que usem APIs que dependem da requisição ou opções de configuração dinâmicas.

### Resolução de rotas \{#route-resolution}

Considere `route` a primitiva de roteamento de nível mais baixo.

- Ele **não** participa de layouts nem de navegações no cliente, como `page` faz.
- **Não pode** haver um arquivo `route.js` na mesma rota que `page.js`.

| Página               | Rota               | Resultado                    |
| -------------------- | ------------------ | ---------------------------- |
| `app/page.js`        | `app/route.js`     | <Cross size={18} /> Conflito |
| `app/page.js`        | `app/api/route.js` | <Check size={18} /> Válido   |
| `app/[user]/page.js` | `app/api/route.js` | <Check size={18} /> Válido   |

Cada arquivo `route.js` ou `page.js` fica responsável por todos os verbos HTTP daquela rota.

```ts filename="app/page.ts" switcher
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}

// Conflict
// `app/route.ts`
export async function POST(request: Request) {}
```

```js filename="app/page.js" switcher
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}

// Conflict
// `app/route.js`
export async function POST(request) {}
```

Leia mais sobre como os Route Handlers [complementam o frontend](/docs/app/guides/backend-for-frontend), ou explore a [Referência da API](/docs/app/api-reference/file-conventions/route) de Route Handlers.

### Helper de contexto da rota \{#route-context-helper}

No TypeScript, você pode tipar o parâmetro `context` dos Route Handlers com o helper globalmente disponível [`RouteContext`](/docs/app/api-reference/file-conventions/route#route-context-helper):

```ts filename="app/users/[id]/route.ts" switcher
import type { NextRequest } from 'next/server'

export async function GET(_req: NextRequest, ctx: RouteContext<'/users/[id]'>) {
  const { id } = await ctx.params
  return Response.json({ id })
}
```

>
> - Os tipos são gerados durante `next dev`, `next build` ou `next typegen`.
