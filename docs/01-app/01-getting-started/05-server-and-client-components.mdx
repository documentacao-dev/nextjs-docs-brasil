Por padrão, layouts e páginas são [Server Components](https://react.dev/reference/rsc/server-components), o que permite buscar dados e renderizar partes da sua UI no servidor, opcionalmente colocar o resultado em cache e fazer streaming dele para o cliente. Quando você precisa de interatividade ou de APIs do navegador, pode usar [Client Components](https://react.dev/reference/rsc/use-client) para adicionar funcionalidades.

Esta página explica como Server e Client Components funcionam no Next.js e quando usá-los, com exemplos de como combiná-los no seu app.

> **Bom saber:** para uma explicação de onde cada tipo de componente roda e de como funciona a fronteira entre eles, veja [A fronteira entre Server e Client](/docs/app/guides/server-and-client-boundary).

## Quando usar Server e Client Components? \{#when-to-use-server-and-client-components}

Os ambientes do cliente e do servidor têm capacidades diferentes. Server e Client Components permitem executar lógica em cada ambiente, dependendo do seu caso de uso.

Use **Client Components** quando precisar de:

- [Estado](https://react.dev/learn/managing-state) e [manipuladores de eventos](https://react.dev/learn/responding-to-events). Ex.: `onClick`, `onChange`.
- [Lógica de ciclo de vida](https://react.dev/learn/lifecycle-of-reactive-effects). Ex.: `useEffect`.
- APIs exclusivas do navegador. Ex.: `localStorage`, `window`, `navigator.geolocation`, etc.
- [Hooks customizados](https://react.dev/learn/reusing-logic-with-custom-hooks).

Use **Server Components** quando precisar de:

- Buscar dados de bancos de dados ou APIs próximos da fonte.
- Usar chaves de API, tokens e outros segredos sem expô-los ao cliente.
- Reduzir a quantidade de JavaScript enviada ao navegador.
- Melhorar o [First Contentful Paint (FCP)](https://web.dev/fcp/) e transmitir o conteúdo progressivamente ao cliente.

Por exemplo, o componente `<Page>` é um Server Component que busca dados sobre um post e os passa como props para o `<LikeButton>`, que cuida da interatividade no cliente.

```tsx filename="app/[id]/page.tsx" highlight={1,17} switcher
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const post = await getPost(id)

  return (
    <div>
      <main>
        <h1>{post.title}</h1>
        {/* ... */}
        <LikeButton likes={post.likes} />
      </main>
    </div>
  )
}
```

```jsx filename="app/[id]/page.js" highlight={1,13} switcher
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({ params }) {
  const { id } = await params
  const post = await getPost(id)

  return (
    <div>
      <main>
        <h1>{post.title}</h1>
        {/* ... */}
        <LikeButton likes={post.likes} />
      </main>
    </div>
  )
}
```

```tsx filename="app/ui/like-button.tsx" highlight={1} switcher
'use client'

import { useState } from 'react'

export default function LikeButton({ likes }: { likes: number }) {
  // ...
}
```

```jsx filename="app/ui/like-button.js" highlight={1} switcher
'use client'

import { useState } from 'react'

export default function LikeButton({ likes }) {
  // ...
}
```

## Como Server e Client Components funcionam no Next.js? \{#how-do-server-and-client-components-work-in-nextjs}

### No servidor \{#on-the-server}

No servidor, o Next.js usa as APIs do React para orquestrar a renderização. O trabalho de renderização é dividido em partes, por segmento de rota individual ([layouts e páginas](/docs/app/getting-started/layouts-and-pages)), incluindo [slots de rotas paralelas](/docs/app/api-reference/file-conventions/parallel-routes), estejam eles exibidos ou não:

- **Server Components** são renderizados em um formato de dados especial chamado React Server Component Payload (RSC Payload).
- **Client Components** e o RSC Payload são usados para fazer o [prerendering](/docs/app/glossary#prerendering) do HTML.

> **O que é o React Server Component Payload (RSC)?**
>
> O RSC Payload é uma representação serializada e compacta da árvore de React Server Components renderizada. O React a usa no cliente para atualizar o DOM do navegador. O RSC Payload contém:
>
> - O resultado renderizado dos Server Components
> - Placeholders indicando onde os Client Components devem ser renderizados e referências aos seus arquivos JavaScript
> - Quaisquer props passadas de um Server Component para um Client Component

### No cliente (primeiro carregamento) \{#on-the-client-first-load}

Em seguida, no cliente:

1. **HTML** é usado para mostrar imediatamente uma prévia rápida e não interativa da rota ao usuário.
2. **RSC Payload** é usado para reconciliar as árvores de Client e Server Components.
3. **JavaScript** é usado para fazer a hydration dos Client Components e tornar o app interativo.

> **O que é hydration?**
>
> Hydration é o processo do React para anexar [manipuladores de eventos](https://react.dev/learn/responding-to-events) ao DOM, tornando o HTML estático interativo.

### Navegações seguintes \{#subsequent-navigations}

Nas navegações seguintes:

- É feito o prefetch do **RSC Payload**, que fica armazenado em cache para uma navegação instantânea.
- **Client Components** são renderizados inteiramente no cliente, sem o HTML renderizado no servidor.

## Exemplos \{#examples}

### Usando Client Components \{#using-client-components}

Você pode criar um Client Component adicionando a diretiva [`"use client"`](https://react.dev/reference/rsc/use-client) no topo do arquivo, acima dos imports.

```tsx filename="app/ui/counter.tsx" highlight={1} switcher
'use client'

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>{count} likes</p>
      <button onClick={() => setCount(count + 1)}>Click me</button>
    </div>
  )
}
```

```jsx filename="app/ui/counter.js" highlight={1} switcher
'use client'

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <p>{count} likes</p>
      <button onClick={() => setCount(count + 1)}>Click me</button>
    </div>
  )
}
```

`"use client"` é usado para declarar uma **fronteira** entre os grafos de módulos (árvores) do Server e do Client.

Depois que um arquivo é marcado com `"use client"`, **todos os seus imports e os componentes que ele renderiza diretamente são incluídos no bundle do cliente**. Isso significa que você não precisa adicionar a diretiva em todo componente destinado ao cliente.

Esse comportamento se aplica aos componentes que fazem parte do [grafo de módulos](/docs/app/glossary#module-graph) de um Client Component, que inclui os módulos que ele importa e os componentes que ele renderiza diretamente. Não se aplica a Server Components passados como `children` ou outras props. Esses componentes não são importados para o grafo de módulos do Client Component. Eles são renderizados no servidor e passados ao Client Component como saída já renderizada.

Veja [Intercalando Server e Client Components](/docs/app/getting-started/server-and-client-components#interleaving-server-and-client-components) para saber como Server e Client Components podem ser combinados.

### Reduzindo o tamanho do bundle JS \{#reducing-js-bundle-size}

Para reduzir o tamanho dos bundles JavaScript do cliente, adicione `'use client'` no topo dos arquivos que definem seus componentes interativos, em vez de marcar grandes partes da UI como Client Components.

Por exemplo, o componente `<Layout>` contém principalmente elementos estáticos, como um logo e links de navegação, mas inclui uma barra de busca interativa. `<Search />` precisa ser um Client Component, enquanto o restante do layout pode continuar sendo um Server Component.

```tsx filename="app/layout.tsx" highlight={12} switcher
// Client Component
import Search from './search'
// Server Component
import Logo from './logo'

// Layout is a Server Component by default
export default function Layout({ children }: { children: React.ReactNode }) {
  return (
    <>
      <nav>
        <Logo />
        <Search />
      </nav>
      <main>{children}</main>
    </>
  )
}
```

```jsx filename="app/layout.js" highlight={12} switcher
// Client Component
import Search from './search'
// Server Component
import Logo from './logo'

// Layout is a Server Component by default
export default function Layout({ children }) {
  return (
    <>
      <nav>
        <Logo />
        <Search />
      </nav>
      <main>{children}</main>
    </>
  )
}
```

```tsx filename="app/ui/search.tsx" highlight={1} switcher
'use client'

export default function Search() {
  // ...
}
```

```jsx filename="app/ui/search.js" highlight={1} switcher
'use client'

export default function Search() {
  // ...
}
```

### Passando dados do Server para Client Components \{#passing-data-from-server-to-client-components}

Você pode passar dados de Server Components para Client Components usando props.

```tsx filename="app/[id]/page.tsx" highlight={1,12} switcher
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  const post = await getPost(id)

  return <LikeButton likes={post.likes} />
}
```

```jsx filename="app/[id]/page.js" highlight={1,8} switcher
import LikeButton from '@/app/ui/like-button'
import { getPost } from '@/lib/data'

export default async function Page({ params }) {
  const { id } = await params
  const post = await getPost(id)

  return <LikeButton likes={post.likes} />
}
```

```tsx filename="app/ui/like-button.tsx" highlight={1} switcher
'use client'

export default function LikeButton({ likes }: { likes: number }) {
  // ...
}
```

```jsx filename="app/ui/like-button.js" highlight={1} switcher
'use client'

export default function LikeButton({ likes }) {
  // ...
}
```

Alternativamente, você pode transmitir dados de um Server Component para um Client Component com a [API `use`](https://react.dev/reference/react/use). Veja um [exemplo](/docs/app/getting-started/fetching-data#streaming-data-with-the-use-api).

> **Bom saber**: props passadas para Client Components precisam ser [serializáveis](https://react.dev/reference/react/use-server#serializable-parameters-and-return-values) pelo React.

### Intercalando Server e Client Components \{#interleaving-server-and-client-components}

Você pode passar Server Components como prop para um Client Component. Isso permite aninhar visualmente UI renderizada no servidor dentro de Client Components.

Um padrão comum é usar `children` para criar um _slot_ em um `<ClientComponent>`. Por exemplo, um componente `<Cart>` que busca dados no servidor, dentro de um componente `<Modal>` que usa estado do cliente para alternar a visibilidade.

```tsx filename="app/ui/modal.tsx" switcher
'use client'

export default function Modal({ children }: { children: React.ReactNode }) {
  return <div>{children}</div>
}
```

```jsx filename="app/ui/modal.js" switcher
'use client'

export default function Modal({ children }) {
  return <div>{children}</div>
}
```

Depois, em um Server Component pai (por exemplo, `<Page>`), você pode passar um `<Cart>` como filho do `<Modal>`:

```tsx filename="app/page.tsx"  highlight={7} switcher
import Modal from './ui/modal'
import Cart from './ui/cart'

export default function Page() {
  return (
    <Modal>
      <Cart />
    </Modal>
  )
}
```

```jsx filename="app/page.js" highlight={7} switcher
import Modal from './ui/modal'
import Cart from './ui/cart'

export default function Page() {
  return (
    <Modal>
      <Cart />
    </Modal>
  )
}
```

Nesse padrão, Server Components são renderizados no servidor antecipadamente, mesmo quando passados como props para Client Components. O React Server Component Payload contém o resultado renderizado desses Server Components, além de placeholders indicando onde os Client Components devem ser renderizados e referências aos seus arquivos JavaScript.

### Providers de context \{#context-providers}

[Context do React](https://react.dev/learn/passing-data-deeply-with-context) é comumente usado para compartilhar estado global, como o tema atual. No entanto, o context do React não tem suporte em Server Components.

Para usar context, crie um Client Component que aceite `children`:

```tsx filename="app/theme-provider.tsx" switcher
'use client'

import { createContext } from 'react'

export const ThemeContext = createContext({})

export default function ThemeProvider({
  children,
}: {
  children: React.ReactNode
}) {
  return <ThemeContext.Provider value="dark">{children}</ThemeContext.Provider>
}
```

```jsx filename="app/theme-provider.js" switcher
'use client'

import { createContext } from 'react'

export const ThemeContext = createContext({})

export default function ThemeProvider({ children }) {
  return <ThemeContext.Provider value="dark">{children}</ThemeContext.Provider>
}
```

Depois, importe-o em um Server Component (por exemplo, `layout`):

```tsx filename="app/layout.tsx" switcher
import ThemeProvider from './theme-provider'

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html>
      <body>
        <ThemeProvider>{children}</ThemeProvider>
      </body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
import ThemeProvider from './theme-provider'

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <ThemeProvider>{children}</ThemeProvider>
      </body>
    </html>
  )
}
```

Seu Server Component agora poderá renderizar o provider diretamente, e todos os outros Client Components do seu app poderão consumir esse context.

> **Bom saber**: renderize providers o mais fundo possível na árvore. Repare que `ThemeProvider` envolve apenas `{children}`, em vez de todo o documento `<html>`. Isso facilita para o Next.js otimizar as partes estáticas dos seus Server Components.

Para passar dados buscados no servidor por meio de context e lê-los em Client Components com `use()`, veja [Usando o `use` do React dentro de um Context Provider](/docs/app/guides/single-page-applications#using-reacts-use-within-a-context-provider).

### Componentes de terceiros \{#third-party-components}

Ao usar um componente de terceiros que depende de recursos exclusivos do cliente, você pode envolvê-lo em um Client Component para garantir que ele funcione como esperado.

Por exemplo, o `<Carousel />` pode ser importado do pacote `acme-carousel`. Esse componente usa `useState`, mas o módulo que o define ainda não tem a diretiva `"use client"`.

Se você usar `<Carousel />` dentro de um Client Component, ele funcionará como esperado:

```tsx filename="app/gallery.tsx" switcher
'use client'

import { useState } from 'react'
import { Carousel } from 'acme-carousel'

export default function Gallery() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <div>
      <button onClick={() => setIsOpen(true)}>View pictures</button>
      {/* Works, since Carousel is used within a Client Component */}
      {isOpen && <Carousel />}
    </div>
  )
}
```

```jsx filename="app/gallery.js" switcher
'use client'

import { useState } from 'react'
import { Carousel } from 'acme-carousel'

export default function Gallery() {
  const [isOpen, setIsOpen] = useState(false)

  return (
    <div>
      <button onClick={() => setIsOpen(true)}>View pictures</button>
      {/*  Works, since Carousel is used within a Client Component */}
      {isOpen && <Carousel />}
    </div>
  )
}
```

No entanto, se você tentar usá-lo diretamente dentro de um Server Component, verá um erro. Isso acontece porque o Next.js não sabe que o `<Carousel />` usa recursos exclusivos do cliente.

Para resolver, envolva os componentes de terceiros que dependem de recursos exclusivos do cliente em seus próprios Client Components:

```tsx filename="app/carousel.tsx" switcher
'use client'

import { Carousel } from 'acme-carousel'

export default Carousel
```

```jsx filename="app/carousel.js" switcher
'use client'

import { Carousel } from 'acme-carousel'

export default Carousel
```

Agora você pode usar `<Carousel />` diretamente dentro de um Server Component:

```tsx filename="app/page.tsx" switcher
import Carousel from './carousel'

export default function Page() {
  return (
    <div>
      <p>View pictures</p>
      {/*  Works, since Carousel is a Client Component */}
      <Carousel />
    </div>
  )
}
```

```jsx filename="app/page.js" switcher
import Carousel from './carousel'

export default function Page() {
  return (
    <div>
      <p>View pictures</p>
      {/*  Works, since Carousel is a Client Component */}
      <Carousel />
    </div>
  )
}
```

> **Recomendação para autores de bibliotecas**
>
> Se você estiver criando uma biblioteca de componentes, adicione a diretiva `"use client"` nos entry points que dependem de recursos exclusivos do cliente. Assim, seus usuários podem importar os componentes em Server Components sem precisar criar wrappers.
>
> Vale notar que alguns bundlers podem remover as diretivas `"use client"`. Você pode encontrar um exemplo de como configurar o esbuild para incluir a diretiva `"use client"` nos repositórios do [React Wrap Balancer](https://github.com/shuding/react-wrap-balancer/blob/main/tsup.config.ts#L10-L13) e do [Vercel Analytics](https://github.com/vercel/analytics/blob/main/packages/web/tsup.config.js#L26-L30).

### Evitando contaminação de ambiente \{#preventing-environment-poisoning}

Módulos JavaScript podem ser compartilhados entre os módulos de Server e de Client Components. Isso significa que é possível importar acidentalmente código exclusivo do servidor no cliente. Por exemplo, considere a seguinte função:

```ts filename="lib/data.ts" switcher
export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}
```

```js filename="lib/data.js" switcher
export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}
```

Essa função contém uma `API_KEY` que nunca deve ser exposta ao cliente.

No Next.js, apenas variáveis de ambiente com o prefixo `NEXT_PUBLIC_` são incluídas no bundle do cliente. Se as variáveis não tiverem esse prefixo, o Next.js as substitui por uma string vazia.

Como resultado, mesmo que `getData()` possa ser importada e executada no cliente, ela não funcionará como esperado.

Para evitar o uso acidental em Client Components, você pode usar o [pacote `server-only`](https://www.npmjs.com/package/server-only).

Depois, importe o pacote em um arquivo que contém código exclusivo do servidor:

```js filename="lib/data.js"
import 'server-only'

export async function getData() {
  const res = await fetch('https://external-service.com/data', {
    headers: {
      authorization: process.env.API_KEY,
    },
  })

  return res.json()
}
```

Agora, se você tentar importar o módulo em um Client Component, haverá um erro em tempo de build.

O pacote [`client-only`](https://www.npmjs.com/package/client-only) correspondente pode ser usado para marcar módulos que contêm lógica exclusiva do cliente, como código que acessa o objeto `window`.

No Next.js, instalar `server-only` ou `client-only` é **opcional**. No entanto, se suas regras de lint apontarem dependências extras, você pode instalá-los para evitar problemas.

```bash package="npm"
npm install server-only
```

```bash package="yarn"
yarn add server-only
```

```bash package="pnpm"
pnpm add server-only
```

```bash package="bun"
bun add server-only
```

O Next.js trata os imports de `server-only` e `client-only` internamente para fornecer mensagens de erro mais claras quando um módulo é usado no ambiente errado. O conteúdo desses pacotes do NPM não é usado pelo Next.js.

O Next.js também fornece suas próprias declarações de tipo para `server-only` e `client-only`, para configurações de TypeScript em que [`noUncheckedSideEffectImports`](https://www.typescriptlang.org/tsconfig/#noUncheckedSideEffectImports) está ativo.
