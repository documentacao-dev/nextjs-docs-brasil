## Tailwind CSS \{#tailwind-css}

O [Tailwind CSS](https://tailwindcss.com/) é um framework CSS utility-first que oferece classes utilitárias de baixo nível para criar designs personalizados.

<AppOnly>

Instale o Tailwind CSS:

```bash package="pnpm"
pnpm add -D tailwindcss @tailwindcss/postcss
```

```bash package="npm"
npm install -D tailwindcss @tailwindcss/postcss
```

```bash package="yarn"
yarn add -D tailwindcss @tailwindcss/postcss
```

```bash package="bun"
bun add -D tailwindcss @tailwindcss/postcss
```

Adicione o plugin do PostCSS ao seu arquivo `postcss.config.mjs`:

```js filename="postcss.config.mjs"
export default {
  plugins: {
    '@tailwindcss/postcss': {},
  },
}
```

Importe o Tailwind no seu arquivo CSS global:

```css filename="app/globals.css"
@import 'tailwindcss';
```

Importe o arquivo CSS no seu layout raiz:

```tsx filename="app/layout.tsx" switcher
import './globals.css'

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
import './globals.css'

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

Agora você já pode usar as classes utilitárias do Tailwind no seu app:

```tsx filename="app/page.tsx" switcher
export default function Page() {
  return (
    <main className="flex min-h-screen flex-col items-center justify-between p-24">
      <h1 className="text-4xl font-bold">Welcome to Next.js!</h1>
    </main>
  )
}
```

```jsx filename="app/page.js" switcher

  return (
    <main className="flex min-h-screen flex-col items-center justify-between p-24">
      <h1 className="text-4xl font-bold">Welcome to Next.js!</h1>
    </main>
  )
}
```

</AppOnly>

## CSS Modules \{#css-modules}

Os CSS Modules limitam o escopo do CSS localmente, gerando nomes de classes únicos. Isso permite usar a mesma classe em arquivos diferentes sem se preocupar com colisões de nomes.

<AppOnly>

Para começar a usar CSS Modules, crie um novo arquivo com a extensão `.module.css` e importe-o em qualquer componente dentro do diretório `app`:

```css filename="app/blog/blog.module.css"
.blog {
  padding: 24px;
}
```

```tsx filename="app/blog/page.tsx" switcher
import styles from './blog.module.css'

export default function Page() {
  return <main className={styles.blog}></main>
}
```

```jsx filename="app/blog/page.js" switcher
import styles from './blog.module.css'

export default function Page() {
  return <main className={styles.blog}></main>
}
```

</AppOnly>

<PagesOnly>

Para começar a usar CSS Modules, crie um novo arquivo com a extensão `.module.css` e importe-o em qualquer componente dentro do diretório `pages`:

```css filename="styles/blog.module.css"
.blog {
  padding: 24px;
}
```

```tsx filename="pages/blog/index.tsx" switcher
import styles from '@/styles/blog.module.css'

export default function Page() {
  return <main className={styles.blog}></main>
}
```

```jsx filename="pages/blog/index.js" switcher
import styles from '@/styles/blog.module.css'

export default function Page() {
  return <main className={styles.blog}></main>
}
```

</PagesOnly>

## CSS global \{#global-css}

Você pode usar CSS global para aplicar estilos em todo o seu app.

<AppOnly>

Crie um arquivo `app/global.css` e importe-o no layout raiz para aplicar os estilos a **todas as rotas** do seu app:

```css filename="app/global.css"
body {
  padding: 20px 20px 60px;
  max-width: 680px;
  margin: 0 auto;
}
```

```tsx filename="app/layout.tsx" switcher
// These styles apply to every route in the application
import './global.css'

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
// These styles apply to every route in the application
import './global.css'

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

> **Bom saber:** estilos globais podem ser importados em qualquer layout, página ou componente dentro do diretório `app`. No entanto, como o Next.js usa o suporte nativo do React a folhas de estilo para integrar com o Suspense, atualmente isso não remove as folhas de estilo ao navegar entre rotas, o que pode gerar conflitos. Recomendamos usar estilos globais apenas para CSS _realmente_ global (como os estilos base do Tailwind), o [Tailwind CSS](#tailwind-css) para estilizar componentes e os [CSS Modules](#css-modules) para CSS com escopo próprio, quando necessário.

</AppOnly>

<PagesOnly>

Importe a folha de estilo no arquivo `pages/_app.js` para aplicar os estilos a **todas as rotas** do seu app:

```jsx filename="pages/_app.js"
import '@/styles/global.css'

export default function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />
}
```

Por causa da natureza global das folhas de estilo, e para evitar conflitos, você deve importá-las dentro de [`pages/_app.js`](/docs/pages/building-your-application/routing/custom-app).

</PagesOnly>

## Folhas de estilo externas \{#external-stylesheets}

<AppOnly>

Folhas de estilo publicadas por pacotes externos podem ser importadas em qualquer lugar do diretório `app`, inclusive em componentes que ficam na mesma pasta:

```tsx filename="app/layout.tsx" switcher
import 'bootstrap/dist/css/bootstrap.css'

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body className="container">{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
import 'bootstrap/dist/css/bootstrap.css'

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body className="container">{children}</body>
    </html>
  )
}
```

> **Bom saber:** no React 19, também é possível usar `<link rel="stylesheet" href="..." />`. Veja a [documentação do `link` no React](https://react.dev/reference/react-dom/components/link) para mais informações.

</AppOnly>

<PagesOnly>

O Next.js permite importar arquivos CSS a partir de um arquivo JavaScript. Isso é possível porque o Next.js estende o conceito de [`import`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Statements/import) além do JavaScript.

### Importe estilos de `node_modules` \{#import-styles-from-node_modules}

Desde o Next.js **9.5.4**, é permitido importar um arquivo CSS de `node_modules` em qualquer lugar do seu app.

Para folhas de estilo globais, como `bootstrap` ou `nprogress`, importe o arquivo dentro de `pages/_app.js`. Por exemplo:

```jsx filename="pages/_app.js"
import 'bootstrap/dist/css/bootstrap.css'

export default function MyApp({ Component, pageProps }) {
  return <Component {...pageProps} />
}
```

Para importar o CSS exigido por um componente de terceiros, você pode fazer isso no componente. Por exemplo:

```jsx filename="components/example-dialog.js"
import { useState } from 'react'
import { Dialog } from '@reach/dialog'
import VisuallyHidden from '@reach/visually-hidden'
import '@reach/dialog/styles.css'

function ExampleDialog(props) {
  const [showDialog, setShowDialog] = useState(false)
  const open = () => setShowDialog(true)
  const close = () => setShowDialog(false)

  return (
    <div>
      <button onClick={open}>Open Dialog</button>
      <Dialog isOpen={showDialog} onDismiss={close}>
        <button className="close-button" onClick={close}>
          <VisuallyHidden>Close</VisuallyHidden>
          <span aria-hidden>×</span>
        </button>
        <p>Hello there. I am a dialog</p>
      </Dialog>
    </div>
  )
}
```

</PagesOnly>

## Ordem e mesclagem \{#ordering-and-merging}

O Next.js otimiza o CSS nos builds de produção dividindo (mesclando) automaticamente as folhas de estilo em partes. A **ordem do seu CSS** depende da **ordem em que você importa os estilos no código**.

Por exemplo, `base-button.module.css` vai ficar antes de `page.module.css`, já que `<BaseButton>` é importado antes de `page.module.css`:

```tsx filename="page.tsx" switcher
import { BaseButton } from './base-button'
import styles from './page.module.css'

export default function Page() {
  return <BaseButton className={styles.primary} />
}
```

```jsx filename="page.js" switcher
import { BaseButton } from './base-button'
import styles from './page.module.css'

export default function Page() {
  return <BaseButton className={styles.primary} />
}
```

```tsx filename="base-button.tsx" switcher
import styles from './base-button.module.css'

export function BaseButton() {
  return <button className={styles.primary} />
}
```

```jsx filename="base-button.js" switcher
import styles from './base-button.module.css'

export function BaseButton() {
  return <button className={styles.primary} />
}
```

### Recomendações \{#recommendations}

Para manter a ordem do CSS previsível:

- Tente concentrar as importações de CSS em um único arquivo de entrada JavaScript ou TypeScript
- Importe estilos globais e folhas do Tailwind na raiz do seu app.
- **Use o Tailwind CSS** para a maioria das necessidades de estilo, já que ele cobre padrões de design comuns com classes utilitárias.
- Use CSS Modules para estilos específicos de componentes quando as classes utilitárias do Tailwind não forem suficientes.
- Adote uma convenção de nomes consistente para os seus CSS Modules. Por exemplo, use `<name>.module.css` em vez de `<name>.tsx`.
- Extraia estilos compartilhados para componentes compartilhados, evitando importações duplicadas.
- Desative linters ou formatadores que ordenam importações automaticamente, como a regra [`sort-imports`](https://eslint.org/docs/latest/rules/sort-imports) do ESLint.
- Você pode usar a opção [`cssChunking`](/docs/app/api-reference/config/next-config-js/cssChunking) no `next.config.js` para controlar como o CSS é dividido.

## Desenvolvimento e produção \{#development-vs-production}

- Em desenvolvimento (`next dev`), as alterações de CSS são aplicadas na hora, com o [Fast Refresh](/docs/architecture/fast-refresh).
- Em produção (`next build`), todos os arquivos CSS são automaticamente concatenados em **vários arquivos `.css` minificados e divididos por rota (code-split)**, garantindo que a menor quantidade possível de CSS seja carregada para cada rota.
- O CSS continua sendo carregado em produção mesmo com o JavaScript desativado, mas em desenvolvimento o JavaScript é necessário para o Fast Refresh.
- A ordem do CSS pode se comportar de forma diferente em desenvolvimento. Sempre confira o build (`next build`) para verificar a ordem final do CSS.
