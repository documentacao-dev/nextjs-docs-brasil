As APIs de Metadata podem ser usadas para definir os metadados do app, para melhorar o SEO e a compartilhabilidade na web, e incluem:

1. [O objeto `metadata` estático](#static-metadata)
2. [A função `generateMetadata` dinâmica](#generated-metadata)
3. [Convenções de arquivo](/docs/app/api-reference/file-conventions/metadata) especiais que podem ser usadas para adicionar [favicons](#favicons) e [imagens OG](#static-open-graph-images) estáticos ou gerados dinamicamente.

Com todas as opções acima, o Next.js gera automaticamente as tags `<head>` relevantes para a página, que podem ser inspecionadas nas ferramentas de desenvolvedor do navegador.

As exportações do objeto `metadata` e da função `generateMetadata` só funcionam em Server Components.

## Campos padrão \{#default-fields}

Há duas tags `meta` padrão que são sempre adicionadas, mesmo que uma rota não defina metadados:

- A [tag meta charset](https://developer.mozilla.org/docs/Web/HTML/Element/meta#attr-charset) define a codificação de caracteres do site.
- A [tag meta viewport](https://developer.mozilla.org/docs/Web/HTML/Viewport_meta_tag) define a largura e a escala da viewport do site para se adaptar a diferentes dispositivos.

```html
<meta charset="utf-8" />
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

Os demais campos de metadados podem ser definidos com o objeto `Metadata` (para [metadados estáticos](#static-metadata)) ou com a função `generateMetadata` (para [metadados gerados](#generated-metadata)).

## Metadados estáticos \{#static-metadata}

Para definir metadados estáticos, exporte um [objeto `Metadata`](/docs/app/api-reference/functions/generate-metadata#metadata-object) de um arquivo [`layout.js`](/docs/app/api-reference/file-conventions/layout) ou [`page.js`](/docs/app/api-reference/file-conventions/page) estático. Por exemplo, para adicionar um título e uma descrição à rota do blog:

```tsx filename="app/blog/layout.tsx" switcher
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'My Blog',
  description: '...',
}

export default function Layout() {}
```

```jsx filename="app/blog/layout.js" switcher
export const metadata = {
  title: 'My Blog',
  description: '...',
}

export default function Layout() {}
```

Você pode ver a lista completa de opções disponíveis na [documentação de `generateMetadata`](/docs/app/api-reference/functions/generate-metadata#metadata-fields).

## Metadados gerados \{#generated-metadata}

Você pode usar a função [`generateMetadata`](/docs/app/api-reference/functions/generate-metadata) para fazer `fetch` de metadados que dependem de dados. Por exemplo, para buscar o título e a descrição de um post específico do blog:

```tsx filename="app/blog/[slug]/page.tsx" switcher
import type { Metadata, ResolvingMetadata } from 'next'

type Props = {
  params: Promise<{ slug: string }>
  searchParams: Promise<{ [key: string]: string | string[] | undefined }>
}

export async function generateMetadata(
  { params, searchParams }: Props,
  parent: ResolvingMetadata
): Promise<Metadata> {
  const slug = (await params).slug

  // fetch post information
  const post = await fetch(`https://api.vercel.app/blog/${slug}`).then((res) =>
    res.json()
  )

  return {
    title: post.title,
    description: post.description,
  }
}

export default function Page({ params, searchParams }: Props) {}
```

```jsx filename="app/blog/[slug]/page.js" switcher
export async function generateMetadata({ params, searchParams }, parent) {
  const slug = (await params).slug

  // fetch post information
  const post = await fetch(`https://api.vercel.app/blog/${slug}`).then((res) =>
    res.json()
  )

  return {
    title: post.title,
    description: post.description,
  }
}

export default function Page({ params, searchParams }) {}
```

### Metadados em streaming \{#streaming-metadata}

Em páginas renderizadas dinamicamente, o Next.js faz streaming dos metadados separadamente, injetando-os no HTML assim que `generateMetadata` resolve, sem bloquear a renderização da interface.

Fazer streaming dos metadados melhora a performance percebida, pois permite que o conteúdo visual chegue primeiro.

O streaming de metadados é **desativado para bots e crawlers** que esperam que os metadados estejam na tag `<head>` (por exemplo, `Twitterbot`, `Slackbot`, `Bingbot`). Eles são detectados pelo header User Agent da requisição recebida.

Você pode personalizar ou **desativar** completamente o streaming de metadados com a opção [`htmlLimitedBots`](/docs/app/api-reference/config/next-config-js/htmlLimitedBots#disabling) no arquivo de configuração do Next.js.

Páginas com prerendering não usam streaming, já que os metadados são resolvidos no build.

Saiba mais sobre [streaming de metadados](/docs/app/api-reference/functions/generate-metadata#streaming-metadata).

### Memoização de requisições de dados \{#memoizing-data-requests}

Pode haver casos em que você precisa buscar os **mesmos** dados para os metadados e para a própria página. Para evitar requisições duplicadas, você pode usar a função [`cache` do React](https://react.dev/reference/react/cache) para memoizar o valor retornado e buscar os dados só uma vez. Por exemplo, para buscar as informações do post do blog tanto para os metadados quanto para a página:

```ts filename="app/lib/data.ts" highlight={5} switcher
import { cache } from 'react'
import { db } from '@/app/lib/db'

// getPost will be used twice, but execute only once
export const getPost = cache(async (slug: string) => {
  const res = await db.query.posts.findFirst({ where: eq(posts.slug, slug) })
  return res
})
```

```js filename="app/lib/data.js" highlight={5} switcher
import { cache } from 'react'
import { db } from '@/app/lib/db'

// getPost will be used twice, but execute only once
export const getPost = cache(async (slug) => {
  const res = await db.query.posts.findFirst({ where: eq(posts.slug, slug) })
  return res
})
```

```tsx filename="app/blog/[slug]/page.tsx" switcher
import { getPost } from '@/app/lib/data'

export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)
  return {
    title: post.title,
    description: post.description,
  }
}

export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)
  return <div>{post.title}</div>
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
import { getPost } from '@/app/lib/data'

export async function generateMetadata({ params }) {
  const { slug } = await params

    title: post.title,

```

## Metadados baseados em arquivos \{#file-based-metadata}

Os seguintes arquivos especiais estão disponíveis para metadados:

- [favicon.ico, apple-icon.jpg e icon.jpg](/docs/app/api-reference/file-conventions/metadata/app-icons)
- [opengraph-image.jpg e twitter-image.jpg](/docs/app/api-reference/file-conventions/metadata/opengraph-image)
- [robots.txt](/docs/app/api-reference/file-conventions/metadata/robots)
- [sitemap.xml](/docs/app/api-reference/file-conventions/metadata/sitemap)

Você pode usá-los para metadados estáticos ou gerar esses arquivos programaticamente com código.

## Favicons \{#favicons}

Favicons são pequenos ícones que representam o site em favoritos e resultados de busca. Para adicionar um favicon ao app, crie um `favicon.ico` e adicione-o na raiz da pasta app.

## Imagens Open Graph estáticas \{#static-open-graph-images}

Imagens Open Graph (OG) são imagens que representam o site nas redes sociais. Para adicionar uma imagem OG estática ao app, crie um arquivo `opengraph-image.jpg` na raiz da pasta app.

Você também pode adicionar imagens OG para rotas específicas criando um `opengraph-image.jpg` mais fundo na estrutura de pastas. Por exemplo, para criar uma imagem OG específica para a rota `/blog`, adicione um arquivo `opengraph-image.jpg` dentro da pasta `blog`.

> Outros formatos de imagem, como `jpeg`, `png` e `gif`, também são aceitos. Veja a [documentação de imagens Open Graph](/docs/app/api-reference/file-conventions/metadata/opengraph-image) para mais informações.

## Imagens Open Graph geradas \{#generated-open-graph-images}

O [construtor `ImageResponse`](/docs/app/api-reference/functions/image-response) permite gerar imagens dinâmicas usando JSX e CSS. Isso é útil para imagens OG que dependem de dados.

Por exemplo, para gerar uma imagem OG única para cada post do blog, adicione um arquivo `opengraph-image.tsx` dentro da pasta `blog/[slug]` e importe o construtor `ImageResponse` de `next/og`:

```tsx filename="app/blog/[slug]/opengraph-image.tsx" switcher
import { ImageResponse } from 'next/og'
import { getPost } from '@/app/lib/data'

// Image metadata
export const size = {
  width: 1200,
  height: 630,
}

export const contentType = 'image/png'

// Image generation
export default async function Image({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = await getPost(slug)

  return new ImageResponse(
    (
      // ImageResponse JSX element
      <div
        style={{
          fontSize: 128,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {post.title}
      </div>
    )
  )
}
```

```jsx filename="app/blog/[slug]/opengraph-image.js" switcher
import { ImageResponse } from 'next/og'
import { getPost } from '@/app/lib/data'

// Image metadata
export const size = {
  width: 1200,
  height: 630,
}

export const contentType = 'image/png'

// Image generation
export default async function Image({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  return new ImageResponse(
    (
      // ImageResponse JSX element
      <div
        style={{
          fontSize: 128,
          background: 'white',
          width: '100%',
          height: '100%',
          display: 'flex',
          alignItems: 'center',
          justifyContent: 'center',
        }}
      >
        {post.title}
      </div>
    )
  )
}
```

`ImageResponse` oferece suporte às propriedades CSS comuns, incluindo flexbox e posicionamento absoluto, fontes personalizadas, quebra de texto, centralização e imagens aninhadas. [Veja a lista completa de propriedades CSS com suporte](/docs/app/api-reference/functions/image-response).

> **Bom saber**:
>
> - Exemplos estão disponíveis no [Vercel OG Playground](https://og-playground.vercel.app/).
> - `ImageResponse` usa [`@vercel/og`](https://vercel.com/docs/og-image-generation), [`satori`](https://github.com/vercel/satori) e `resvg` para converter HTML e CSS em PNG.
> - Só há suporte a flexbox e a um subconjunto de propriedades CSS. Layouts avançados (por exemplo, `display: grid`) não funcionam.
