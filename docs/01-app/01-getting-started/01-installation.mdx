Crie um novo app Next.js e execute-o localmente.

## Início rápido \{#quick-start}

1. Crie um novo app Next.js chamado `my-app`
2. Use `cd my-app` e inicie o dev server.
3. Acesse `http://localhost:3000`.

```bash package="pnpm"
pnpm create next-app@latest my-app --yes
cd my-app
pnpm dev
```

```bash package="npm"
npx create-next-app@latest my-app --yes
cd my-app
npm run dev
```

```bash package="yarn"
yarn create next-app@latest my-app --yes
cd my-app
yarn dev
```

```bash package="bun"
bun create next-app@latest my-app --yes
cd my-app
bun dev
```

- `--yes` pula os prompts usando preferências salvas ou padrões. A configuração padrão ativa TypeScript, Tailwind CSS, ESLint, App Router e Turbopack, com o alias de importação `@/*`, e inclui o `AGENTS.md` para orientar agentes de código a escrever código Next.js atualizado.

</AppOnly>

## Requisitos do sistema \{#system-requirements}

Antes de começar, confira se seu ambiente de desenvolvimento atende aos seguintes requisitos:

- Versão mínima do Node.js: [20.9](https://nodejs.org/)
- Sistemas operacionais: macOS, Windows (incluindo WSL) e Linux.

## Navegadores compatíveis \{#supported-browsers}

O Next.js funciona com navegadores modernos sem nenhuma configuração.

- Chrome 111+
- Edge 111+
- Firefox 111+
- Safari 16.4+

Saiba mais sobre o [suporte a navegadores](/docs/architecture/supported-browsers), incluindo como configurar polyfills e definir navegadores específicos como alvo.

## Criar com a CLI \{#create-with-the-cli}

A forma mais rápida de criar um novo app Next.js é usando o [`create-next-app`](/docs/app/api-reference/cli/create-next-app), que configura tudo automaticamente para você. Para criar um projeto, execute:

```bash package="pnpm"
pnpm create next-app
```

```bash package="npm"
npx create-next-app@latest
```

```bash package="yarn"
yarn create next-app
```

```bash package="bun"
bun create next-app
```

Durante a instalação, você verá os seguintes prompts:

```txt filename="Terminal"
What is your project named? my-app
Would you like to use the recommended Next.js defaults?
    Yes, use recommended defaults - TypeScript, ESLint, No React Compiler, Tailwind CSS, No src/ directory, Cache Components, AGENTS.md
    No, reuse previous settings
    No, customize settings - Choose your own preferences
```

Se você escolher `customize settings`, verá os seguintes prompts:

```txt filename="Terminal"
Would you like to use TypeScript? No / Yes
Which linter would you like to use? ESLint / Biome / None
Would you like to use React Compiler? No / Yes
Would you like to use Tailwind CSS? No / Yes
Would you like your code inside a `src/` directory? No / Yes
Would you like to use Cache Components? No / Yes
Would you like to customize the import alias (`@/*` by default)? No / Yes
What import alias would you like configured? @/*
Would you like to include AGENTS.md to guide coding agents to write up-to-date Next.js code? No / Yes
```

Depois dos prompts, o [`create-next-app`](/docs/app/api-reference/cli/create-next-app) vai criar uma pasta com o nome do seu projeto e instalar as dependências necessárias.

## Instalação manual \{#manual-installation}

Para criar um novo app Next.js manualmente, instale os pacotes necessários:

```bash package="pnpm"
pnpm i next@latest react@latest react-dom@latest
```

```bash package="npm"
npm i next@latest react@latest react-dom@latest
```

```bash package="yarn"
yarn add next@latest react@latest react-dom@latest
```

```bash package="bun"
bun add next@latest react@latest react-dom@latest
```

> **Bom saber:**
>
> - O `App Router` usa por padrão as [versões canary do React](https://react.dev/blog/2023/05/03/react-canaries), que incluem todas as mudanças estáveis do React 19, além de recursos mais novos que estão sendo validados em frameworks. Mesmo assim, você deve declarar react e react-dom no package.json para garantir compatibilidade com as ferramentas e com o ecossistema.
> - O `Pages Router` usa a versão do React definida no seu `package.json`.

Depois, adicione os seguintes scripts ao seu arquivo `package.json`:

```json filename="package.json"
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start",
    "lint": "eslint",
    "lint:fix": "eslint --fix"
  }
}
```

Esses scripts correspondem às diferentes etapas de desenvolvimento de um app:

- `next dev`: inicia o dev server usando o Turbopack (bundler padrão).
- `next build`: gera o build do app para produção.
- `next start`: inicia o servidor de produção.
- `eslint`: executa o ESLint.

O Turbopack agora é o bundler padrão. Para usar o webpack, execute `next dev --webpack` ou `next build --webpack`. Veja a [documentação do Turbopack](/docs/app/api-reference/turbopack) para detalhes de configuração.

### Crie o diretório `app` \{#create-the-app-directory}

O Next.js usa roteamento baseado no sistema de arquivos, ou seja, as rotas do seu app são definidas pela forma como você organiza os arquivos.

Crie uma pasta `app`. Depois, dentro dela, crie um arquivo `layout.tsx`. Esse arquivo é o [layout raiz](/docs/app/api-reference/file-conventions/layout#root-layout). Ele é obrigatório e precisa conter as tags `<html>` e `<body>`.

```tsx filename="app/layout.tsx" switcher
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

```jsx filename="app/layout.js" switcher
export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}
```

Crie uma página inicial `app/page.tsx` com um conteúdo inicial:

```tsx filename="app/page.tsx" switcher
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}
```

```jsx filename="app/page.js" switcher
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}
```

Tanto `layout.tsx` quanto `page.tsx` serão renderizados quando o usuário acessar a raiz do seu app (`/`).

### Crie o diretório `pages` \{#create-the-pages-directory}

O Next.js usa roteamento baseado no sistema de arquivos, ou seja, as rotas do seu app são definidas pela forma como você organiza os arquivos.

Crie um diretório `pages` na raiz do projeto. Depois, adicione um arquivo `index.tsx` dentro da pasta `pages`. Ele será sua página inicial (`/`):

```tsx filename="pages/index.tsx" switcher
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}
```

```jsx filename="pages/index.js" switcher
export default function Page() {
  return <h1>Hello, Next.js!</h1>
}
```

Em seguida, adicione um arquivo `_app.tsx` dentro de `pages/` para definir o layout global. Saiba mais sobre o [arquivo App personalizado](/docs/pages/building-your-application/routing/custom-app).

```tsx filename="pages/_app.tsx" switcher
import type { AppProps } from 'next/app'

export default function App({ Component, pageProps }: AppProps) {
  return <Component {...pageProps} />
}
```

```jsx filename="pages/_app.js" switcher
export default function App({ Component, pageProps }) {
  return <Component {...pageProps} />
}
```

Por fim, adicione um arquivo `_document.tsx` dentro de `pages/` para controlar a resposta inicial do servidor. Saiba mais sobre o [arquivo Document personalizado](/docs/pages/building-your-application/routing/custom-document).

```tsx filename="pages/_document.tsx" switcher
import { Html, Head, Main, NextScript } from 'next/document'

export default function Document() {
  return (
    <Html>
      <Head />
      <body>
        <Main />
        <NextScript />
      </body>
    </Html>
  )
}
```

```jsx filename="pages/_document.js" switcher
import { Html, Head, Main, NextScript } from 'next/document'

export default function Document() {
  return (
    <Html>
      <Head />
      <body>
        <Main />
        <NextScript />
      </body>
    </Html>
  )
}
```

### Crie a pasta `public` (opcional) \{#create-the-public-folder-optional}

Crie uma [pasta `public`](/docs/app/api-reference/file-conventions/public-folder) na raiz do projeto para armazenar arquivos estáticos, como imagens, fontes etc. Os arquivos dentro de `public` podem ser referenciados no seu código a partir da URL base (`/`).

Depois, você pode referenciar esses arquivos usando o caminho raiz (`/`). Por exemplo, `public/profile.png` pode ser referenciado como `/profile.png`:

```tsx filename="app/page.tsx" highlight={4} switcher
import Image from 'next/image'

export default function Page() {
  return <Image src="/profile.png" alt="Profile" width={100} height={100} />
}
```

```jsx filename="app/page.js" highlight={4} switcher
import Image from 'next/image'

export default function Page() {
  return <Image src="/profile.png" alt="Profile" width={100} height={100} />
}
```

## Execute o dev server \{#run-the-development-server}

1. Execute `npm run dev` para iniciar o dev server.
2. Acesse `http://localhost:3000` para ver seu app.
3. Edite o arquivo <AppOnly>`app/page.tsx`</AppOnly><PagesOnly>`pages/index.tsx`</PagesOnly> e salve para ver o resultado atualizado no navegador.

## Configure o TypeScript \{#set-up-typescript}

> Versão mínima do TypeScript: `v5.1.0`

O Next.js já vem com suporte nativo ao TypeScript. Para adicionar TypeScript ao seu projeto, renomeie um arquivo para `.ts` / `.tsx` e execute `next dev`. O Next.js vai instalar automaticamente as dependências necessárias e adicionar um arquivo `tsconfig.json` com as opções de configuração recomendadas.

## Configure seu editor \{#set-up-your-editor}

O App Router nomeia arquivos por convenção, como `page.tsx`, `layout.tsx` e `route.ts`, então o editor logo fica cheio de abas com o mesmo nome. Identifique cada aba com as pastas em que ela está, como `blog/[id]`, para diferenciá-las.

No VS Code 1.88+ ou no Cursor, adicione [rótulos de editor personalizados](https://code.visualstudio.com/updates/v1_88#_customize-editor-labels) ao `.vscode/settings.json`. Usar rótulos com duas pastas de profundidade evita que rotas dinâmicas como `blog/[id]/page.tsx` fiquem todas com o mesmo rótulo `[id]`:

```json filename=".vscode/settings.json"
{
  "workbench.editor.customLabels.patterns": {
    "**/app/**/page.tsx": "${dirname(1)}/${dirname} - page.tsx",
    "**/app/**/layout.tsx": "${dirname(1)}/${dirname} - layout.tsx",
    "**/app/**/loading.tsx": "${dirname(1)}/${dirname} - loading.tsx",
    "**/app/**/error.tsx": "${dirname(1)}/${dirname} - error.tsx",
    "**/app/**/not-found.tsx": "${dirname(1)}/${dirname} - not-found.tsx",
    "**/app/**/template.tsx": "${dirname(1)}/${dirname} - template.tsx",
    "**/app/**/default.tsx": "${dirname(1)}/${dirname} - default.tsx",
    "**/app/**/route.ts": "${dirname(1)}/${dirname} - route.ts"
  }
}
```

Ou copie este prompt para que seu agente de código faça a configuração:

```prompt
Set up custom editor labels so my Next.js App Router files are easy to tell apart. Read https://nextjs.org/docs/app/getting-started/installation#set-up-your-editor and add the workbench.editor.customLabels.patterns config shown there to my .vscode/settings.json, creating the file if it doesn't exist. Adjust the labels to taste. If I use a different editor, apply the equivalent setting or tell me it's automatic, and leave my other settings untouched.
```

> **Bom saber:** as IDEs da JetBrains (WebStorm, IntelliJ) mostram automaticamente a pasta dos arquivos com o mesmo nome, então não é preciso configurar nada.

</AppOnly>

## Configure o linting \{#set-up-linting}

O Next.js oferece suporte a linting com ESLint ou Biome. Escolha um linter e execute-o diretamente pelos scripts do `package.json`.

- Use o **ESLint** (regras abrangentes):

```json filename="package.json"
{
  "scripts": {
    "lint": "eslint",
    "lint:fix": "eslint --fix"
  }
}
```

- Ou use o **Biome** (linter + formatador rápido):

```json filename="package.json"
{
  "scripts": {
    "lint": "biome check",
    "format": "biome format --write"
  }
}
```

Se seu projeto já usava `next lint`, migre seus scripts para a CLI do ESLint com o codemod:

```bash filename="Terminal"
npx @next/codemod@canary next-lint-to-eslint-cli .
```

Se você usar o ESLint, crie uma configuração explícita (recomendado: `eslint.config.mjs`). O ESLint aceita tanto [o formato legado `.eslintrc.*` quanto o novo formato `eslint.config.mjs`](https://eslint.org/docs/latest/use/configure/configuration-files#configuring-eslint). Veja a [referência da API do ESLint](/docs/app/api-reference/config/eslint#with-core-web-vitals) para uma configuração recomendada.

> **Bom saber:** a partir do Next.js 16, o `next build` não executa mais o linter automaticamente. Em vez disso, você pode executar seu linter pelos scripts do NPM.

Veja a página do [plugin do ESLint](/docs/app/api-reference/config/eslint) para mais informações.

## Configure importações absolutas e aliases de caminhos de módulos \{#set-up-absolute-imports-and-module-path-aliases}

O Next.js tem suporte nativo às opções `"paths"` e `"baseUrl"` dos arquivos `tsconfig.json` e `jsconfig.json`.

Essas opções permitem criar aliases de diretórios do projeto para caminhos absolutos, deixando as importações de módulos mais simples e limpas. Por exemplo:

```jsx
// Before
import { Button } from '../../../components/button'

// After
import { Button } from '@/components/button'
```

Para configurar importações absolutas, adicione a opção `baseUrl` ao seu arquivo `tsconfig.json` ou `jsconfig.json`. Por exemplo:

```json filename="tsconfig.json or jsconfig.json"
{
  "compilerOptions": {
    "baseUrl": "src/"
  }
}
```

Além de configurar o `baseUrl`, você pode usar a opção `"paths"` para criar `"alias"` de caminhos de módulos.

Por exemplo, a configuração a seguir mapeia `@/components/*` para `components/*`:

```json filename="tsconfig.json or jsconfig.json"
{
  "compilerOptions": {
    "baseUrl": "src/",
    "paths": {
      "@/styles/*": ["styles/*"],
      "@/components/*": ["components/*"]
    }
  }
}
```

Cada um dos `"paths"` é relativo à localização do `baseUrl`.

## Atualize seu app Next.js \{#upgrade-your-nextjs-app}

Mantenha a versão do Next.js atualizada. Cada release traz correções de segurança, correções de bugs e otimizações de performance junto com novos recursos, e manter-se atualizado deixa cada atualização pequena. Execute o comando `upgrade`:

```bash package="pnpm"
pnpm next upgrade
```

```bash package="npm"
npx next upgrade
```

```bash package="yarn"
yarn next upgrade
```

```bash package="bun"
bunx next upgrade
```

Atualizar também atualiza a documentação incluída no pacote `next`, em `node_modules/next/dist/docs/`. Novos recursos chegam com a documentação deles, e as páginas existentes ganham orientações novas e armadilhas descobertas ao longo do caminho. Os [agentes de código com IA](/docs/app/guides/ai-agents) do seu projeto passam então a trabalhar com a versão que você tem instalada, em vez de depender dos dados de treinamento.

Para que um agente de código faça e verifique a atualização, execute `npx next@canary upgrade --agent=latest`. Veja [Atualizar com um agente de código](/docs/app/guides/upgrading/agent-upgrade) para outras políticas.

Veja [Atualização](/docs/app/getting-started/upgrading) para guias de versão e passos de atualização manual, ou a [documentação de preview](https://preview.nextjs.org) para conhecer recursos antes de chegarem a uma versão estável.
