Os erros podem ser divididos em duas categorias: [erros esperados](#handling-expected-errors) e [exceções não capturadas](#handling-uncaught-exceptions). Esta página mostra como tratar esses erros no seu app Next.js.

## Tratamento de erros esperados \{#handling-expected-errors}

Erros esperados são aqueles que podem acontecer durante a operação normal do app, como os da [validação de formulário no servidor](/docs/app/guides/forms) ou de requisições que falham. Esses erros devem ser tratados explicitamente e retornados ao cliente.

### Server Functions \{#server-functions}

Você pode usar o hook [`useActionState`](https://react.dev/reference/react/useActionState) para tratar erros esperados em [Server Functions](https://react.dev/reference/rsc/server-functions).

Para esses erros, evite usar blocos `try`/`catch` e lançar erros. Em vez disso, modele os erros esperados como valores de retorno.

```ts filename="app/actions.ts" switcher
'use server'

export async function createPost(prevState: any, formData: FormData) {
  const title = formData.get('title')
  const content = formData.get('content')

  const res = await fetch('https://api.vercel.app/posts', {
    method: 'POST',
    body: { title, content },
  })
  const json = await res.json()

  if (!res.ok) {
    return { message: 'Failed to create post' }
  }
}
```

```js filename="app/actions.js" switcher
'use server'

  const content = formData.get('content')

    body: { title, content },

```

Você pode passar sua action para o hook `useActionState` e usar o `state` retornado para exibir uma mensagem de erro.

```tsx filename="app/ui/form.tsx" highlight={11,19} switcher
'use client'

import { useActionState } from 'react'
import { createPost } from '@/app/actions'

const initialState = {
  message: '',
}

export function Form() {
  const [state, formAction, pending] = useActionState(createPost, initialState)

  return (
    <form action={formAction}>
      <label htmlFor="title">Title</label>
      <input type="text" id="title" name="title" required />
      <label htmlFor="content">Content</label>
      <textarea id="content" name="content" required />
      {state?.message && <p aria-live="polite">{state.message}</p>}
      <button disabled={pending}>Create Post</button>
    </form>
  )
}
```

### Server Components \{#server-components}

Ao buscar dados dentro de um Server Component, você pode usar a resposta para renderizar condicionalmente uma mensagem de erro ou um [`redirect`](/docs/app/api-reference/functions/redirect).

```tsx filename="app/page.tsx" switcher
export default async function Page() {
  const res = await fetch(`https://...`)
  const data = await res.json()

  if (!res.ok) {
    return 'There was an error.'
  }

  return '...'
}
```

```jsx filename="app/page.js" switcher

```

### Não encontrado \{#not-found}

Você pode chamar a função [`notFound`](/docs/app/api-reference/functions/not-found) dentro de um segmento de rota e usar o arquivo [`not-found.js`](/docs/app/api-reference/file-conventions/not-found) para mostrar uma interface de 404.

```tsx filename="app/blog/[slug]/page.tsx" switcher
import { notFound } from 'next/navigation'
import { getPostBySlug } from '@/lib/posts'

export default async function Page({
  params,
}: {
  params: Promise<{ slug: string }>
}) {
  const { slug } = await params
  const post = getPostBySlug(slug)

  if (!post) {
    notFound()
  }

  return <div>{post.title}</div>
}
```

```jsx filename="app/blog/[slug]/page.js" switcher
import { notFound } from 'next/navigation'
import { getPostBySlug } from '@/lib/posts'

export default async function Page({ params }) {
  const { slug } = await params
  const post = getPostBySlug(slug)

  if (!post) {
    notFound()
  }

  return <div>{post.title}</div>
}
```

```tsx filename="app/blog/[slug]/not-found.tsx" switcher
export default function NotFound() {
  return <div>404 - Page Not Found</div>
}
```

```jsx filename="app/blog/[slug]/not-found.js" switcher
export default function NotFound() {
  return <div>404 - Page Not Found</div>
}
```

## Tratamento de exceções não capturadas \{#handling-uncaught-exceptions}

Exceções não capturadas são erros inesperados que indicam bugs ou problemas que não deveriam acontecer no fluxo normal do seu app. Eles devem ser tratados lançando erros, que serão capturados pelos error boundaries.

### Error boundaries aninhados \{#nested-error-boundaries}

O Next.js usa error boundaries para tratar exceções não capturadas. Error boundaries capturam erros nos componentes filhos e exibem uma interface de fallback no lugar da árvore de componentes que quebrou.

Crie um error boundary adicionando um arquivo [`error.js`](/docs/app/api-reference/file-conventions/error) dentro de um segmento de rota e exportando um componente React:

```tsx filename="app/dashboard/error.tsx" switcher
'use client' // Error boundaries must be Client Components

import { useEffect } from 'react'

export default function ErrorPage({
  error,
  retry,
}: {
  error: unknown
  retry: () => void
}) {
  useEffect(() => {
    // Log the error to an error reporting service
    console.error(error)
  }, [error])

  return (
    <div>
      <h2>Something went wrong!</h2>
      <button
        onClick={
          // Attempt to recover by re-fetching and re-rendering the segment
          () => retry()
        }
      >
        Try again
      </button>
    </div>
  )
}
```

```jsx filename="app/dashboard/error.js" switcher
'use client' // Error boundaries must be Client Components

import { useEffect } from 'react'

export default function ErrorPage({ error, retry }) {
  useEffect(() => {

    <div>
      <h2>Something went wrong!</h2>
      <button
        onClick={

```

Os erros sobem até o error boundary pai mais próximo. Isso permite um tratamento de erros granular, ao colocar arquivos `error.tsx` em diferentes níveis da [hierarquia de rotas](/docs/app/getting-started/project-structure#component-hierarchy).

Para a recuperação de erros em nível de componente, a função [`catchError`](/docs/app/api-reference/functions/catchError) permite criar error boundaries que podem envolver qualquer parte da árvore de componentes:

```tsx filename="app/custom-error-boundary.tsx" switcher
'use client'

import { catchError, type ErrorInfo } from 'next/error'

function ErrorFallback(props: { title: string }, { error, retry }: ErrorInfo) {
  const message = error instanceof Error ? error.message : String(error)

  return (
    <div>
      <h2>{props.title}</h2>
      <p>{message}</p>
      <button onClick={() => retry()}>Try again</button>
    </div>
  )
}

export default catchError(ErrorFallback)
```

```jsx filename="app/custom-error-boundary.js" switcher
'use client'

import { catchError } from 'next/error'

function ErrorFallback(props, { error, retry }) {
  const message = error instanceof Error ? error.message : String(error)

  return (
    <div>
      <h2>{props.title}</h2>
      <p>{message}</p>
      <button onClick={() => retry()}>Try again</button>
    </div>
  )
}

export default catchError(ErrorFallback)
```

Depois, use o componente retornado para envolver qualquer layout ou página:

```tsx filename="app/some-component.tsx" switcher
import ErrorBoundary from './custom-error-boundary'

export default function Component({ children }: { children: React.ReactNode }) {
  return <ErrorBoundary title="Dashboard Error">{children}</ErrorBoundary>
}
```

```jsx filename="app/some-component.js" switcher
import ErrorBoundary from './custom-error-boundary'

export default function Component({ children }) {
  return <ErrorBoundary title="Dashboard Error">{children}</ErrorBoundary>
}
```

Error boundaries não capturam erros dentro de manipuladores de eventos. Eles foram feitos para capturar erros [durante a renderização](https://react.dev/reference/react/Component#static-getderivedstatefromerror) e mostrar uma **interface de fallback** em vez de derrubar o app inteiro.

Em geral, erros em manipuladores de eventos ou em código assíncrono não são tratados por error boundaries, porque são executados depois da renderização.

Para tratar esses casos, capture o erro manualmente e armazene-o com `useState` ou `useReducer`, depois atualize a interface para informar o usuário.

```tsx
'use client'

import { useState } from 'react'

export function Button() {
  const [error, setError] = useState(null)

  const handleClick = () => {
    try {
      // do some work that might fail
      throw new Error('Exception')
    } catch (reason) {
      setError(reason)
    }
  }

  if (error) {
    /* render fallback UI */
  }

  return (
    <button type="button" onClick={handleClick}>
      Click me
    </button>
  )
}
```

Observe que erros não tratados dentro de `startTransition`, do `useTransition`, vão se propagar até o error boundary mais próximo.

```tsx
'use client'

import { useTransition } from 'react'

export function Button() {
  const [pending, startTransition] = useTransition()

  const handleClick = () =>
    startTransition(() => {
      throw new Error('Exception')
    })

  return (
    <button type="button" onClick={handleClick}>
      Click me
    </button>
  )
}
```

### Erros globais \{#global-errors}

Embora sejam menos comuns, você pode tratar erros no layout raiz usando o arquivo [`global-error.js`](/docs/app/api-reference/file-conventions/error#global-error), localizado na pasta raiz do app, mesmo ao usar [internacionalização](/docs/app/guides/internationalization). A interface de erro global precisa definir suas próprias tags `<html>` e `<body>`, já que ela substitui o layout ou template raiz quando está ativa.

```tsx filename="app/global-error.tsx" switcher
'use client' // Error boundaries must be Client Components

export default function GlobalError({
  error,
  retry,
}: {
  error: unknown
  retry: () => void
}) {
  return (
    // global-error must include html and body tags
    <html>
      <body>
        <h2>Something went wrong!</h2>
        <button onClick={() => retry()}>Try again</button>
      </body>
    </html>
  )
}
```

```jsx filename="app/global-error.js" switcher
'use client' // Error boundaries must be Client Components

export default function GlobalError({ error, retry }) {
  return (
    // global-error must include html and body tags
    <html>
      <body>
        <h2>Something went wrong!</h2>
        <button onClick={() => retry()}>Try again</button>
      </body>
    </html>
  )
}
```
